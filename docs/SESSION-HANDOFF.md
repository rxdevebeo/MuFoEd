## 1. Что это за проект

Rust-библиотека для чтения WordprocessingML, рендеринга в SVG/PDF и отчёта о
поддержке. Ядро — **WordprocessingML Strict** (ISO/IEC 29500-1). С прошлой
сессии добавлена нормализация **Transitional → Strict**, потому что 99 % реальных
документов — Transitional.

Основание: `TZ-STRICT-OOXML-RUST.md`. Заказы: `STAGE-{1..6}-TASK.md`,
`STAGE-6-TASK.md`. Реестр условных приёмок: `docs/waivers.toml`.

## 4. Незакоммиченная работа (главное на сейчас)

Ветка `stage-8-pdf`, последний коммит `a5d3507` (`strict-ooxml-write`).
В дереве поверх него — незакоммиченное:

```
M Cargo.lock, Cargo.toml
M strict-ooxml-cli/src/main.rs
M strict-ooxml-render-svg/src/{fields,font/builtin,font/mod,layout/mod,lib,math/layout,
                                 notes,paint/graphics,paint/image}.rs
?? strict-ooxml-render-pdf/
```

`strict-ooxml-render-pdf` **не проходит `cargo fmt --check`** (минимум три
расхождения в `src/document.rs`) и не проверен. `strict-ooxml-render-svg`
собирается.

## 5. Главное, что надо понять про состояние

**«Корпус 36/36 открывается» — это про открытие, а не про верность.**

```
36 документов   318 страниц   8 с графикой   0 страниц пустых
```

Ни одна из 318 страниц не сравнивается ни с чем: WPS-эталонов для
Transitional нет. `Интегралы (2).docx` рендерится в одну страницу с тремя
текстовыми узлами. Мы измерили «не упало», а не «похоже на оригинал».
Это самое слабое утверждение в проекте, и оно про 99 % реальности.

Красный тест — **не авария, а результат.** Граница центроида 24 px у класса
`formulas` не была пределом: это было значение, вмещавшее `strict-stage5c`
стр.1, а за ним прятались ещё две фикстуры. Теперь гейт называет все четыре
сразу, с измерениями.

## 6. Задачи по приоритету

### №1. Дать Transitional-корпусу гейт точности — *разблокировано, нужен WPS*

318 страниц реального содержимого без проверки. Действие: 8–12 документов
(с графикой обязательно), WPS-эталоны, та же таблица классов из
`coverage/render-gates.toml`. **WPS есть у заказчика, здесь
`kwpsconvert` не установлен** — эталоны генерировать на своей машине.

### №2. Сломать шрифтовую запутанность — *нужна одна проверка заказчика*

Два независимых пункта уперлись в одно: бокс блока 5C и константы
интервалов. Два провала на одном камне — камень и есть приоритет.

Причина: эталон — **Cambria Math**, мы рисуем **STIX Two Math**. Зазор,
измеренный в эталоне, = интервал раскладки + разница двух гарнитур.
`strict-ooxml-render-pdf` это **не снимает**: он встраивает тот же
подставной шрифт.

**Ход:** PDF несёт точные позиции глифов. Сравнивать *геометрию раскладки*
(позиции, advances) вместо пикселей — тогда форма глифа не участвует.
**Проверить: даёт ли экспорт PDF из WPS извлекаемые позиции текста?** Одна
команда снимает блокировку с обоих пунктов.

Пока не снято — константы помечены `verified = false` (как
`normalize::tables::RENAMES`), а граница центроида `formulas` снята до 2.5
и остаётся красной.

### №3. Идемпотентность раунд-трипа — *не ждёт ничего, делать сейчас*

```
normalize(parse(serialize(parse(normalize(x))))) == normalize(x)
```

Не требует ни WPS, ни шрифта, ни эталонов. Ловит потерю информации в
самом нормализаторе — а это **единственный слой, который стирает содержимое
по замыслу**: VML, OLE, `w:ptab`, `w:compat` в `REMOVALS`. `write` уже
landed (`a5d3507`), так что инвариант реализуем сразу.

### Ниже

- **Класс `formulas` вне своих границ** (4 страницы из 9). Задокументирован
  в `5C-C4`. Починка **заблокирована №2** — поэтому не приоритет, хотя
  единственное, что сейчас красное.
- **`max_extent_px = 18`** у того же класса — та же болезнь: равно измеренным
  18.00 px. Следующий на снятие.
- **Карты покрытия самопроверяемые** (`A-2`, `A-5B-2`, `COVERAGE-5C`).
  Процессное, дорогое, технически ничего не блокирует.

### Зависимости

```
№2 (шрифт) ──┬──► починка класса formulas
              └──► калибровка интервалов по эталону
№1 (эталоны Transitional) ──► настоящая метрика точности на 99 % реальности
№3 (идемпотентность) ──► страховка нормализатора, ни от кого не зависит
```

## 7. Конвенции и уроки

1. **Приёмка ≠ зелёные тесты.** Проверять независимым оракулом. Уроки D-1/D-2,
   C-3 были скрыты самосогласованными фикстурами.
2. **Independent oracle обязателен:** внешний ZIP (`zip`), внешний XML
   (`roxmltree`), внешняя схема (`jsonschema`), WPS-эталоны для рендера.
3. **Каждый этап оформляется заказом** (требования + критерии) и
   **приёмочным документом**; код в заказах не приводится.
4. **Строгость namespace:** Strict (`purl.oclc.org/ooxml`) vs Transitional
   (`schemas.openxmlformats.org`).
5. **Лицензии:** сторонние фикстуры/шрифты — только MIT/Apache-2.0/OFL.
6. **Без `unwrap`/паник** в библиотечных путях; лимиты ресурсов обязательны;
   **неподдержанное не терять молча** (`SupportModel`, `LossRecord`).

### Уроки именно этой сессии

7. **Проверка, которая не может сработать, хуже её отсутствия** — она
   создаёт видимость контроля. Граница сдвига 12 px при окне поиска ±12.
8. **Мёртвый фильтр хуже отсутствующего.** Порог по строке не видел
   вертикальную линейку (3 px × 1000 строк ≈ 3 px на строку). Кумулятивный
   подсчёт — вижу.
9. **Граница, подогнанная под измеренный дефект, перестаёт быть границей.**
   Их в проекте было три (центроид 24, extent 18, `codegen-units`), все три
   снимались и выяснялось, что за ними — настоящие ошибки.
10. **Отказ должен называть измерения, а не только нарушенный предел.**
    Иначе три фикстуры молча падают за одной.
11. **Визуальная проверка окупается за один прогон** — просмотрщик нашёл
    нулевой зазор между `ln` и чертой дроби, который шесть месяцев жил в
    отчёте как «широкие допуски».
12. **«Открывается» ≠ «верно»** — см. §5.

## 8. Риски / подводные камни

- **Strict-файлов в природе почти нет.** Поиск дал 2 файла во всём GitHub.
  Реальные документы — Transitional, отсюда и нормализация.
- **Запутанность «эталон/шрифт»** блокирует всё, что касается точности
  (§6 №2). Это главный риск проекта.
- WPS/шрифты пиннятся по версии; эталоны генерируются один раз (в CI WPS нет).
- SSIM зависит от шрифтов/DPI: растеризатор обязан получать бандл-шрифты.
- Пагинация (2↔1) — проверять на каждом изменении layout.
- `max_compression_ratio` не занижать (легитимные docx дают ~228:1).
- **Красный тест в `main` нельзя чинить расширением границы** — это тот же
  антипаттерн, что и снимаем.

## 9. Как собирать и проверять

```text
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features          # 1 красный — см. §5
cargo deny check

# Гейт точности (подробный вывод)
cargo test -p strict-ooxml-render-svg --test ssim -- --nocapture

# Нормализация Transitional
cargo run -p strict-ooxml-cli -- check <file.docx> --transitional
cargo run -p strict-ooxml-cli -- normalize <file.docx>

# Просмотрщик
cargo run -p strict-ooxml-view -- strict-ooxml-core/tests/docx --transitional
```

Покрытие в CI задаётся `CARGO_PROFILE_DEV_CODEGEN_UNITS=1` — см. §10 п.4.
