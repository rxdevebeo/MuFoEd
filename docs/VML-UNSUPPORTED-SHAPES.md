# VML: примеры неподдерживаемых фигур

Снимок исходников на 2026-10-11. Документ сводит примеры из имеющихся тестов и корпусных заметок, чтобы оценить, какие расширения конвертера выглядят практичными. Это не каталог всех VML-фигур стандарта.

## Краткий вывод

В текущем коде распознаются элементы `shape`, `rect`, `roundrect`, `oval` и `line`. Для обычного `shape` дополнительно нужен распознаваемый `type`, `path`, текстовый блок, текстовый путь или картинка. Если классификатор не находит drawable-элемент или `settle` не может определить тип фигуры, он возвращает `None`; при политике `VmlFallback::Convert` такой VML-блок удаляется и регистрируется как потеря `T7.vml`.

В найденных корпусных примерах есть достоверный случай **частичной**, а не полной потери: freeform path с дуговой командой `r`. Его рамка конвертируется, а контур опускается. В репозитории не нашлось конкретного тестового XML с тегами `<v:arc>`, `<v:curve>` или `<v:polyline>`; ниже они приведены только как иллюстрации форм, которые текущий список тегов не распознаёт, не как найденные корпусные документы.

| Отдельный `<v:arc>` | Конкретного fixture в проверенных тестах/поиске по репозиторию не найдено. | Тег не входит в drawable-набор `classify` (`shape/rect/roundrect/oval/line`), поэтому фигура не классифицируется и VML-поддерево удаляется при `Convert`. | Добавлять только после fixture с реальными атрибутами/геометрией и проверки перевода размеров, углов, заливки и обводки. |
| Отдельные `<v:curve>` и `<v:polyline>` | Конкретных fixture в проверенных тестах/поиске не найдено. | Эти теги также не входят в drawable-набор `classify`; блок целиком удаляется при `Convert`. | Для `curve` проверить поддержку кубической кривой в целевой DrawingML-модели; для `polyline` — семантику последовательности точек и замыкания. | `v:shape` с неизвестным `type`, без path/текста/картинки | Условие следует из `preset_of` + `settle`; отдельный минимальный fixture для этой комбинации не найден. | `preset_of` не определяет preset; `settle` возвращает `None`, фигура удаляется как неподдерживаемая VML. | Сопоставлять таблицу известных `shapetype`/`type` с DrawingML presets. Неизвестные типы сохранять в отчёте с именем и `type`, чтобы строить приоритеты по реальным документам. |

## Контрольные примеры, которые уже поддерживаются

Это полезные положительные случаи для сравнения при расширении:

- Корпусный плавающий `<v:rect ...><w10:wrap type="topAndBottom"/></v:rect>` классифицируется как `Shape::Rectangle`, а тип обтекания и отступ сохраняются: `strict-ooxml-core/src/normalize/vml.rs`, тест `the_corpus_floating_shapes_classify_and_keep_their_wrap` (строки 1798–1809).
- В `strict-ooxml-core/src/normalize/transitional.rs` есть fixture с `v:line`, `v:rect` и `v:shape`-WordArt, подтверждающие обработку линий, прямоугольников и текстовых путей (около строк 3514–3550).
- `path_is_convertible` допускает только буквы команд `m`, `l`, `c`, `x`, `e`, `n`, `f`, `s`; unit test явно противопоставляет корпусный дуговой path и простой `m0,0l100,100x` (`strict-ooxml-core/src/normalize/vml.rs`, строки 1813–1816).

## Как выбирался материал

Проверены классификатор и преобразование VML в `strict-ooxml-core/src/normalize/vml.rs` и `strict-ooxml-core/src/normalize/transitional.rs`, тестовые XML и текстовые упоминания по проекту. Индекс графа показал текущие определения, но файловая метаинформация после индексации менялась, поэтому выводы сверены с исходным кодом. Поиск текстовых fixtures не покрывает бинарные DOCX-файлы, исключённые Git-правилами или лежащие вне проверенных текстовых источников; следовательно, отсутствие примеров `<v:arc>`/`<v:curve>`/`<v:polyline>` в этом документе не доказывает, что их нет в любых пользовательских документах.
