# Импорт DjVu и OCR

## Запуск

```powershell
cargo +1.92.0 run -p strict-ooxml-cli -- from-djvu book.djvu --out book.docx
cargo +1.92.0 run -p strict-ooxml-cli -- djvu-dump book.djvu
cargo +1.92.0 run -p strict-ooxml-cli -- from-djvu book.djvu --out excerpt.docx --pages 3-8 --mode visual
cargo +1.92.0 run -p strict-ooxml-cli --features ocr-ollama -- from-djvu scan.djvu --out scan.docx --ocr --ocr-model qwen3-vl:8b-instruct-ctx16k
```

CLI по умолчанию работает без сетевого OCR. `--ocr` требует feature
`ocr-ollama`; параметры `--ocr-model` и `--ocr-endpoint` требуют `--ocr`.
Ollama должен предоставлять модель с vision-входом. Можно задать `OLLAMA_HOST`
и `OLLAMA_MODEL`; существующий OCR-клиент ограничивает время
запроса и размер ответа. `--no-images` отключает вложение сканов, но не OCR,
если он был явно включён. `.djvu` и `.djv` принимаются как пути к файлу;
формат определяется по магии, а не по расширению.

Коды возврата: **0** — документ записан без потерь (оценки `Inferred`
остаются в отчёте); **1** — записан с сообщёнными потерями/ограничениями;
**2** — ошибка входа, параметров или записи. Код 1 не означает, что DOCX отсутствует.
OCR-провенанс записывается как `Recovered`; отсутствие исходного слоя остаётся
отдельным фактом. CLI всегда печатает conversion report и потери writer.

## Библиотека

Meta-crate `strict-ooxml`: `djvu` — ридер и конвертер текста;
`djvu-image` — native растр для сканов и OCR; `ocr-ollama` — transport.
`strict-ooxml-convert` предоставляет аналогичные фичи. Сам
`strict-ooxml-djvu` по умолчанию не содержит image-кодеков.

```rust,ignore
use strict_ooxml::{DjvuDocument, DjvuLimits, DjvuOptions, convert_djvu};
let bytes = std::fs::read("book.djvu")?;
let mut reader = DjvuDocument::open(&bytes, DjvuLimits::default())?;
let converted = convert_djvu(&mut reader, &DjvuOptions::default())?;
// Передайте converted.document и converted.media в write_package/MediaBag.
```

С feature `djvu-image` `DjvuOptions::text_recovery(Arc<dyn TextRecovery>)`
принимает пользовательский provider без сетевой зависимости. Ответ ограничен
`max_recovered_text_bytes` (1 MiB по умолчанию), включая ответы собственного provider.

## Текст, геометрия и OCR

- `Readable`: native paragraph/line zones становятся WML-абзацами в исходном
  порядке. OCR не вызывается. Шрифт/кегль оцениваются по **словам/строкам**,
  а не полной высоте многострочного абзаца; начертание не выдумывается.
- `Empty`: полного текстового чанка нет. Поддерживаемый скан может быть
  вложен как PNG; если PNG содержит чернила и provider задан, вызывается OCR.
- `Unusable`: текстовый чанк есть, но дерево отсутствует/повреждено.
  Доступный UTF-8 сохраняется без геометрии; причина записывается в отчёт.
  OCR не заменяет исходный текст.
- OCR-абзацы получают стиль `Recovered` и запись с моделью/версией.
  Ответ модели не содержит координат, поэтому точные базовые линии не заявляются.
  При отказе, timeout, пустом/слишком большом ответе скан и документ сохраняются.
- Пустой белый растр не отправляется модели. Unsupported image layer
  запрещает неполный композит: provider не получает картинку с потерянным слоем.

`semantic` даёт редактируемый native текст. `visual` использует абзац на строку,
отступы и estimated exact leading; это приближение по box-геометрии, а не
гарантия исходной типографики. Каждая выбранная страница имеет WML-секцию
с собственными размерами. Сканы и OCR-текст идут последовательно; OCR
не является невидимым searchable overlay и может увеличить число Word-страниц.

## Контейнер и бюджеты

Ридер не обращается к сети или файловой системе сам. Для indirect DjVu
`open_with_resolver` принимает явный provider компонентных файлов. CLI
разрешает только файлы внутри канонического каталога входа; ссылки,
выходящие из каталога, отклоняются. Ограничения считаются по сумме всех файлов
и расширенных INCL; циклы отклоняются. Unicode-ID поддерживаются.

По умолчанию: 2048 страниц, 2 млн чанков/включений, 512 MiB на payload,
2 GiB на все компоненты, 4 MiB на BZZ-блок, 64 MiB text buffer на страницу,
500 тыс. зон, глубина 16, 4096 компонентов, 256 MiB суммарных копий текста зон,
16 Mi pixels на страницу/плоскость (CLI `--max-image-pixels N` позволяет явно
изменить этот бюджет). JB2 record budget ограничивается также
upstream ceiling 65 536; upstream symbol-pixel/work caps сохраняются.
Лимиты проверяются перед соответствующим выделением/циклом; фактические
размеры JB2 проверяются независимо от INFO. IW44-плоскости проверяются до decode.

Растр не кэшируется между вызовами API; конвертер декодирует каждую нужную
страницу один раз и одновременно держит только её декодированные плоскости.
Encoded PNG вложения остаются в `Converted.media` до записи пакета.

## Ограничения

Декодируются JPEG (`BGjp`/`FGjp`), палитра `FGbz` поверх indexed JB2,
обычный CCITT G4 `Smmr` и standalone legacy `FORM:PM44`/`FORM:BM44`.
Striped Smmr пока отклоняется явно: формат framing полос ещё не подтверждён
независимым вектором. Legacy IW44 не содержит INFO: размеры берутся из header,
для физического размера страницы принимается 100 dpi с записью в отчёт.
JPEG header проверяется до pixel decode; FGbz проверяет каждую ссылку на цвет,
длину таблицы и соответствие числу JB2 blit records. Конфликтующие маски и
цветовые слои отклоняются, чтобы OCR не получал неоднозначный композит. Фигуры
на странице с native текстом собираются из двух сигналов. Первый — связные
компоненты битональной маски `Sjbz`, которые текст покрывает менее чем наполовину
(перекрытие по площади, а не «центр внутри зоны»); второй — области, где
**фоновый слой** (`BG44`/JPEG/legacy `PM44`/`BM44`) не белый: это фотография,
которую маска не различает, и она берётся целиком поверх наложенного текста.
Кандидаты кластеризуются (зазор масштабируется с размером страницы), порог —
доля площади `recovery_mixed_min_area_ratio`, вырезка уходит в `FigureClassifier`,
а ответ становится `wp:docPr/@descr`/`@title`; не распознанное как фигура
отражается в отчёте. Сканы без текста с классификатором описываются как фигура,
и только распознанные как `scan` уходят в OCR. Оглавление `NAVM` становится плоскими
`w:bookmarkStart` на целевых страницах с заголовком пункта; уровень вложенности
из-за плоской природы закладок Word не сохраняется и отмечается в отчёте.
`maparea` становятся `w:hyperlink` на словах под
прямоугольником: внешние — с `r:id`, внутренние (`#page=N`, `±N`, id/заголовок) —
с закладкой на целевой странице и `w:anchor`; неразрешённые и не покрывшие текст
ссылки отражаются в отчёте. `(metadata (Title …) (Author …) (Subject …) (Keywords …))`
переносится в `docProps/core.xml`, а отсутствующие там поля заполняются из XMP
(`dc:title`/`dc:creator`/`dc:description`/`dc:subject`/`pdf:Keywords`); нативные
ключи `(metadata …)` приоритетнее. Ридер сообщает о наличии
этих механизмов. Неизвестные чанки пропускаются с агрегированным счётчиком.

IW44-плоскости увеличиваются ближайшим пикселем; reference gamma/interpolation
не заявлены точными. Поворот растра применяется по INFO; ориентация координат
native зон пока считается unrotated и помечается как неподтверждённое допущение.
Поэтому SC-D7 для всего корпуса и SC-D14 не объявлены закрытыми.
