# Приёмка изменений по аудитам и текущая база StrictLib

Дата: 5 октября 2026 года. Проверен HEAD `b413b1594447458fac8101093b6502eacf4ff661`, `master`. Исходное рабочее дерево было чистым. Производственный код по результатам этой проверки не изменён. Созданы отчёт, заказ и воспроизводимые свидетельства.

**Решение: частичная приёмка.** Интегрированные исправления сохраняем как рабочую базу. Объявлять все аудиты закрытыми нельзя: расширение проверки обнаружило порчу текста, невалидный Strict и ошибки обтекания. Для планирования использовать этот статус и [заказ R01–R11](AUDIT_REWORK_ORDER_2026-10-05.md).

## Новый корпус CC0_DOCX

Проверены все 100 файлов `testdata/CC0_DOCX/manifest.json`: размеры и SHA-256 совпадают. Manifest декларирует CC0 и provenance; самостоятельная юридическая проверка происхождения не проводилась.

| Измерение | Результат |
|---|---|
| Запись Transitional | 100 выходов: 34 Clean, 66 Degraded |
| Повторное открытие | 100/100 завершились успешно |
| Следующая запись в Strict | 100 выходов: 45 Clean, 55 Degraded |
| Неизменность ZIP parts при следующей записи | 98/100; два изменения текста |
| Рендер первой страницы | 100/100 exit 0, SVG присутствуют |
| XSD Strict-выходов | 100 документов проверены; 39 642 сообщения, 21 группа |
| OPC выходов | 100 пакетов, 0 нарушений |

Код 1 записи означает Degraded. Код 0 самого probe означает завершение измерения, а не успешную приёмку. Проверка fixed point сравнивает содержимое ZIP parts; это не доказательство семантической сохранности первого преобразования. Рендер всех страниц, визуальная точность и полноценный multilingual layout пока не приняты.

Два документа — `025_iyothee_dass_thoughts_religion.docx` и `080_makkal_sattam_1.docx` — меняют `word/document.xml`: удаляется ведущий U+FEFF и дублируется последний тамильский комбинируемый знак. Независимый минимальный [leading-feff.docx](audit-review-2026-10-05/leading-feff.docx) подтверждает порчу при первой записи с exit 0: `U+FEFF + தமிழ்` превращается в `தமிழ்்`. Причина в parser пока требует локализации; наблюдаемая порча доказана.

Из XSD-сообщений 39 013 относятся к `rFonts` (`hint="cs"` недопустим в Strict). Другие крупные группы: `placeholder` 477, `documentProtection` 35. Всего 39 635 сообщений не классифицированы registry, 7 классифицированы как source chart violations. Нулевой счётчик `ours` здесь не означает отсутствие дефекта: входные Transitional roots текущий Strict oracle пропускает. Для остальных групп требуется анализ source/output и исправление или доказанная классификация. [Примеры ошибок](audit-review-2026-10-05/cc0-xsd-examples.json) и [полный лог](audit-review-2026-10-05/cc0-xsd.log) сохранены.

## Что остаётся ограничением или непроверенным

- Кубические кривые, clip, pattern, tight-contour, through-contour остаются явно неподдерживаемыми; добавление новых примитивов — отдельное планирование.
- Для F16 нет эталона Word, требуемого исходным контрактом. WPS-эталон уже показывает дефекты и пригоден для диагностики; он не становится утверждённой заменой без решения владельца.
- Старое название «приватный корпус не прогонялся» больше не описывает доступный local corpus: 121 документ теперь измерен census. Иные недоступные приватные наборы этим не приняты.
- Историческая Linux coverage: core 90,71%, fidelity 91,01%, wml 83,06%, report 96,57%, svg 84,80%; относится к `015e0c7` с локальными изменениями. Это не свежий coverage HEAD. Старый контракт wml ≥85% и целевые файлы core 100% не выполнен этими цифрами.
- Исторический fuzz — восемь целей по 60 секунд. Требуемый длительный прогон по 3600 секунд не выполнен здесь.
- Последний проверенный успешный внешний [CI run 37195191322](https://github.com/rxdevebeo/MuFoEd/actions/runs/37195191322) относится к `7a8e6d3`. Master впереди origin/master на 6 коммитов; внешний CI текущего HEAD не принят.
- Существующие waivers и зависимость AUD-99 от upstream hayro сохраняются для отдельного решения. Workspace PASS не закрывает их автоматически.
- Работы RTF/DjVu в других ветках и расширение редактора K00–K15 не входят в эту принятую базу master.

## Воспроизводимость и основание для следующего плана

Проверялись источники, тесты, первоначальные контракты `REWORK-AUDIT-2026-10.md`, `docs/acceptance-AUD-00-12.md`, `docs/audit-2026-10-04/{AUDIT,FIX_PLAN,REPORT,CLOSURE}.md`, CI и текущие результаты. Использован граф Tier 2 с проверкой coverage путей и прямым чтением существенного исходного кода. Metadata freshness потребовала source fallback. Корпуса и target исключены из графа и проверены напрямую. Отсутствие recorded graph gaps не трактуется как доказательство полноты.

Свежие команды, exit codes и SHA-256 логов находятся в [verification.json](audit-review-2026-10-05/verification.json); данные нового корпуса — [cc0-summary.json](audit-review-2026-10-05/cc0-summary.json), [cc0-results.json](audit-review-2026-10-05/cc0-results.json) и [cc0_probe.py](audit-review-2026-10-05/cc0_probe.py). Полные локальные сборки и логи — `target/acceptance-2026-10-05/`. Эти target-артефакты не являются долговечным Git-архивом. Сохранённые в docs компактные свидетельства позволяют восстановить обнаруженные дефекты.

Практическая база: DOCX pipeline и имеющиеся regression paths работают, поддерживаемая область ограничена. Очередь начинается с сохранности текста и валидности выходов, затем обтекания/layout и достоверной приёмки. Новый продуктовый план строить после R11 либо явно принять частичную базу с перечисленными ограничениями. Исполнение доработок не выполнено этим отчётом; [файл заказа](AUDIT_REWORK_ORDER_2026-10-05.md) содержит владение, зависимости, матрицы и критерии завершения каждой работы.
