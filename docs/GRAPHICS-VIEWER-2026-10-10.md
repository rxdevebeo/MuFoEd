# Графика и визуальный просмотрщик — 2026-10-10

Просмотрщик: `http://127.0.0.1:8741/`. В меню корпусов сначала находится
`graphics-gallery`, затем реальные Strict/Transitional DOCX. Масштаб меняется
ползунком; документы выбираются через Documents, предупреждения раскрываются
в компактной панели losses, свёрнутой по умолчанию. Даже раскрытая панель
прокручивается отдельно и оставляет основное пространство документу.
Внизу виден индикатор загрузки: ожидание ответа без выдуманных процентов,
затем прогресс вывода страниц. Страницы остаются доступными при предупреждениях.

Повторный запуск из корня репозитория:

```powershell
./xtool/visual-viewer.ps1
# После изменения исходников:
./xtool/visual-viewer.ps1 -Rebuild
```

Нужен Cargo с toolchain 1.92.0 в PATH. Сервер слушает только loopback.
Если порт занят уже запущенным просмотрщиком, используйте его либо укажите
другой порт: `-Port 8742`. Скрипт не завершает чужие процессы.

## Реализовано

- Предупреждения SVG передаются в pipeline просмотрщика. Общие предупреждения
  компоновки учитываются один раз, без выдуманного номера страницы.
- Открытие, компоновка и отрисовка используют общий OpenControl с дедлайном;
  сервер запускает отдельный процесс и завершает его по таймауту или превышению
  бюджета памяти. Подробности: `VIEWER-MEMORY-2026-10-10.md`.
- Кэш каждого корпуса ограничен восемью документами и 64 MiB учитываемых
  метаданных/диагностики. SVG страниц HTTP-просмотрщика хранится во временных
  файлах, удаляемых при освобождении последнего владельца документа.
  Это ограничение удерживаемого кэша, а не общего RSS:
  временные данные компоновки, копии ответов и память браузера сюда не входят.
- Просмотр показывает все страницы документа. Ограничения в 200 страниц и
  32 МиБ суммарного SVG удалены. Браузер держит до шести SVG и подгружает
  остальные при прокрутке, сохраняя место каждой страницы.
- Линейные градиенты с цветными остановками в общей модели размещения,
  SVG `linearGradient` и PDF axial shading. Заливка ограничена контуром фигуры.
- PDF-читатель сохраняет поддерживаемые RGB axial shading с линейными
  функциями и одним контуром отсечения в Vector.gradient. Остальные виды
  shading и пересечения clip paths остаются явно отмеченной потерей.
  Конвертер PDF → DOCX пока сообщает `vector.gradient` как unsupported.
- Повторяющиеся узоры: горизонтальная/вертикальная штриховка, сетки,
  диагонали, шахматная заливка и процентные точки. Общая модель выдаёт SVG
  pattern и PDF tiling pattern. Плотности и рисунки являются детерминированной
  реализацией; точное совпадение каждого пресета с Word не установлено.
- `tight` и `through` для простых контуров: исключается весь охват полосы
  строки, учитываются отступы; `through` допускает текст в вогнутые промежутки.
  Контуры с менее чем тремя или более чем 2048 точками явно предупреждают.
- Нелинейное `a:path` градиента сохраняется при parse/write/reopen; рендер
  использует первый цвет с предупреждением вместо ложного линейного градиента.

## Границы поддержки

Это не полная поддержка сложной графики Office. Остаются нелинейные градиенты,
все прочие pattern presets, точное соответствие узоров Word, clipping
изображений к произвольной фигуре, lockedCanvas и полноценная раскладка SmartArt.
Существующий рендер SmartArt использует кэшированное drawing представление.
Самопересекающиеся контуры и точность сложного обтекания не приняты визуально.

Единицы wrapPolygon задаются явно через
`RenderOptions::wrap_coordinates(WrapCoordinates::Office21600)` для Office,
либо `Emu` (по умолчанию) для стандартной модели и VML-нормализации.
По умолчанию режим берётся из самих точек: контур, укладывающийся в 21600 при extent заметно больше, читается как Office-пространство, иначе — EMU (VML-нормализованные контуры).
Office использует пространство 21600 × 21600 вместо единиц EMU стандарта:
[разъяснение Microsoft Open Specifications](https://learn.microsoft.com/en-us/answers/questions/405731/unit-for-coordinates-of-points-in-wrappolygon).

## Проверки

- SVG: независимая растеризация resvg, цветовые и contour assertions.
- PDF: независимая проверка структуры lopdf и пикселей hayro, включая clipping.
- Запись: сохранение path shading при parse/write/reopen.
- Viewer: отмена, вытеснение кэша, предупреждения, сохранение всех 201 страниц
  регрессионного документа и время жизни временных файлов.
- Edge: девять документов после выполнения JS, SVG definitions, страницы и
  предупреждения; дополнительно индикатор при задержке реального запроса и
  панель с 1000 предупреждениями. Отчёт и снимки:
  `render_out/graphics-gallery/browser-report.json`.
- Логи проверок: `tests-final.log` (основные пакеты до остановки на fixture
  viewer без pgSz), `tests-completion.log` (успешный повтор viewer/WML/write
  после исправления fixture), `pdf-final.log`, `doctests-final.log`,
  `tests-recheck.log`, `viewer-ui-tests.log`, `clippy.log`, `fmt.log`
  в той же папке. Сравнение с эталонным экспортом Word для новой галереи
  не выполнялось.
