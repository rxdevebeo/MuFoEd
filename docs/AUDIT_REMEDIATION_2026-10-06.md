## Исправлено

1. **PDF Metric терял `f`/`i` в слове `office`.** Сборщик subset учитывает `TextItem.advance`: Metric включает scalar glyph/CID mappings, Shaped сохраняет shaped clusters. Новый тест `strict-ooxml-render-pdf/tests/metric_ligatures.rs` проверяет `office`, `ffi`, смешанные Metric/Shaped на одном face, Shaped combining sequence, число фактически записанных PDF glyph operators и ToUnicode через lopdf. Missing-glyph report не подавляется. Произвольный отдельно нарисованный combining glyph при отсутствии его в выбранном face этим исправлением не создаётся.
2. **ASan leak неизвестного PDF image filter.** `Box::leak` удалён: `Reject::UnsupportedFilter` владеет `String`. Старые сохранённые leak inputs воспроизведены: до исправления exit 77, после исправления PDF и convert targets —exit 0. Есть unit test времени жизни/текста причины отказа. Это изменение публичного типа: payload теперь `String`, `Reject` больше не `Copy`; остаётся `Clone`. Внешним callers при необходимости потребуется явный clone/borrow.
3. **Stack overflow глубокой OMML в Windows debug Rust 1.98.** Воспроизведён hostile-тест `a_formula_nested_past_its_depth_budget_is_degraded_the_same_way`; создание вариантов `MathNode` вынесено из рекурсивного dispatcher в `build_math_node`. Тот же тест зелёный; все 43 hostile-теста зелёные в debug и release. Стек 1 МиБ и ограничения XML/math/text-box не увеличены. Это дополнительный выявленный дефект; исходное утверждение про текстовые рамки не переписано в утверждение про все рекурсивные пути.
4. **Writer дублировал relationships.** Body allocation и перенос исходных relationships повторно создавали одинаковые ссылки; пять исходных OPC-нарушений на двух локальных документах превращались в десять выходных. `RelBuilder` и `RelAllocator` теперь различают type/target/mode и переиспользуют совпадающую identity через BTreeMap. Публичный тест `relationship_identity.rs` проверяет один выходной hyperlink, сохранение исходного Target и fixed-point повторной записи; unit controls различают тип и режим. После исправления 221/221 OPC: source=5, output=5, introduced=0. Эти пять нарушений не называются schema-clean.
5. **Census сравнивал неверную identity relationships, процентов и QName.** rId и имя media part могут измениться без смены ресурса. Сопоставление выполняется до вычитания multisets по type/mode и SHA-256 содержимого; одинаковый rId с другим ресурсом больше не маскирует изменение. DrawingML проценты сравниваются с целочисленной формой только на явно перечисленных типах; angles/coordinates и чужое namespace этим правилом не оправдываются. Element/parent/attribute namespaces входят в identity: только известные Transitional/Strict пары канонизируются, а чужой namespace не компенсирует потерю одноимённого узла или атрибута. Добавлен `--inventory-out` для полной машинной выгрузки. Итоговый полный selftest, включая положительные/отрицательные controls и последние изменения полей detail, проходит (exit 0).
6. **WML branch threshold.** Добавлены проверки сохранности содержимого при повреждённых свойствах, foreign OMML children, nested row/cell SDT и неполных settings entries. На Linux nightly, cargo-llvm-cov 0.9.1, codegen-units=1: **736/1042 =70,63%**, lines **8007/9167 =87,35%**. Пороги не менялись.
7. **D07: отпечаток F21 зависел только от `git status`.** Теперь он включает рабочие байты tracked и non-ignored untracked файлов, имена и статус. Потоковое чтение не загружает весь корпус в память. Контроль на временном Git-репозитории проверяет два разных содержимых при одинаковом статусе, стабильность неизменённого дерева и смену байтов untracked файла; commits не создаются. `unknown` при ошибке чтения остаётся неприемлемым receipt. Отдельный code manifest выше исключает изменяемые артефакты и идентифицирует код независимо от документальных receipts.
