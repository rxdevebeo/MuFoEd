## 2. Как гонять гейт на этой машине

Две ловушки окружения, на которых гейт «падает», хотя код ни при чём:

- `xtool` запускать с тем же тулчейном: `cargo +1.92.0 run -q -p xtool -- …`
  (без `+1.92.0` берётся системный 1.91.1 и сборка отказывает по MSRV).
- Python-гейты требуют `lxml`; он есть в `py -3.11`, а не в `python` (miniconda):
  `py -3.11 xtool/xsd-gate/xsd_gate.py`, `py -3.11 xtool/xsd-gate/census_gate.py --quiet-messages`.

Проверка «падает до правки» без порчи рабочего дерева:

```powershell
git worktree add --detach D:\projects\StrictLib-acc <коммит-до-правки>
# подставить новые тестовые файлы, затем:
$env:CARGO_TARGET_DIR='D:\projects\StrictLib-acc-target'
cargo +1.92.0 test -p <crate> --all-features --test <file> <фильтр>
git worktree remove --force D:\projects\StrictLib-acc
```

Тесты, которые роняют процесс (переполнение стека), запускать **по одному** фильтром — иначе
падает весь бинарь и остальные результаты не видны.

### Д-2. AUD-07: `math.rs` — на `nested`, `enter`/`leave` недоступны вне обёртки

**Что не так.** В `strict-ooxml-wml/src/parse/math.rs` 23 функции вызывают `parser.enter()?` /
`parser.leave()` напрямую. Это компилируется, потому что `math` — дочерний модуль `parse`, а
приватные методы `PartParser` видны потомкам модуля. Живой утечки сейчас нет (между парами нет
ранних `return Ok` и ошибки нигде не глотаются), но первый же ранний выход вернёт исходный
дефект. Строка статуса AUD-07 утверждает обратное («77 функций … переведены»).

**Что сделать.**
1. Все 23 пары в `math.rs` → `parser.nested(|parser| { … })`, по образцу уже переведённых
   файлов (`fonts.rs`, `settings.rs`). `MathScope::enter/leave` (счётчик формулы, AUD-06) не
   трогать — это другой счётчик.
2. Сделать обход невозможным по построению: вынести счётчик в подмодуль
   `strict-ooxml-wml/src/parse/depth.rs` — структура `Depth { depth: u32, max: u32 }` с
   **приватными** `enter`/`leave` и `pub(super)` методом, через который реализован
   `PartParser::nested`; поле `depth` у `PartParser` заменить на `Depth`. Тогда `enter`/`leave`
   видны только внутри `depth.rs`, и прямой вызов из `math.rs` (или любого будущего файла) — ошибка
   компиляции. `debug_depth()` (`#[cfg(test)]`) читать через `Depth`.
3. Поправить строку AUD-07 в таблице статуса плана: сколько функций переведено и что
   `enter`/`leave` теперь закрыты модулем.

**Тесты.** Новый тест «падает до правки» здесь невозможен — живого дефекта нет, это
устранение возможности его внести. Вместо него:
- свойство `depth == 0` после разбора (уже есть в `parse::tests`) прогнать на фикстуре с
  формулами всех видов, которые разбирают функции из `math.rs` (дробь, радикал, индексы,
  `nary`, `d`, `m`, `eqArr`, `func`, `groupChr`, `bar`, `box`, `borderBox`, `acc`, `limLow/Upp`,
  `sPre`, `phant`), и на той же фикстуре, обрезанной внутри формулы (ошибка, не паника);
- в описании коммита указать, что §0.1 п.2 неприменим и почему.

Тест `300 w:font` из AUD-07 на старом коде проходит: утечка в `parse/fonts.rs` была на корне
таблицы шрифтов, а корень в части один, поэтому одна утечка до предела 256 не дорастает и
никакое число шрифтов её не ловит. Оставить тест как контрольный и сказать это в его
комментарии.

**Приёмка Д-2.** `rg "\.enter\(\)" strict-ooxml-wml/src` — совпадения только в `parse/depth.rs`;
`rg "\.leave\(\)" strict-ooxml-wml/src` — то же (вызовы `scope.leave()` счётчика формулы
допустимы); гейт зелёный; коммит `fix(wml): AUD-07 …`; строка AUD-07 снова ✅.
