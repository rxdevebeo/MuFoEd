## 1. Заключение

**Частично. Проект уже представляет собой работающее библиотечное ядро DOCX → модель WordprocessingML → запись DOCX → SVG/PDF, с программным редактированием. Однако выход не всегда соответствует Strict-схеме, а реализованный PDF → Strict путь содержит существенные потери. Приемка всей заявленной задачи не завершена.**

Писатель способен создавать валидные пакеты Strict, а не просто меняет расширение. Нормализация Transitional интегрирована в чтение пакета. Есть модель документа, исходные медиаданные, отчеты о поддержке и потерях, рендереры, CLI и локальный просмотрщик. Эти возможности подтверждены кодом и выполненными тестами. Но приписывать каждому выходу статус Strict нельзя: в полном census 20 из 121 выходных документов имеют схемные нарушения, а гейт все равно печатает PASS (A05/A09).

Но «файл соответствует схеме Strict» и «исходный документ сохранен» — разные свойства. В пробах получены Strict-файлы с потерянной графикой и границами PDF-страниц. Они проходят XSD и OPC, а CLI возвращает `0`. Поэтому положительный ответ для всей цепочки сейчас был бы необоснованным.

Практическая оценка:

- **DOCX Strict/Transitional:** пригодное ядро для контролируемого подмножества, но с найденными дефектами сериализации Strict. Отчетов недостаточно: для приемки результата нужен независимый XSD-контроль, учитывающий также неизвестные нарушения.
- **PDF с текстовым слоем:** импорт реализован, но требует исправления потери страниц, графики и геометрии до приемки как надежного преобразования.
- **Сканированный PDF:** инфраструктура OCR есть в библиотечных модулях; обычный CLI не предоставляет настройки модели распознавания. Получение редактируемого текста скана через стандартную команду не обеспечено.
- **Редактирование:** доступно через Rust API. Полноценного пользовательского редактора и встроенного контроля согласованности измененной модели пока нет.
- **Другие форматы:** импорта DOC, ODT, RTF, HTML, TXT, DjVu, XLSX и PPTX в текущем workspace/CLI не обнаружено. Это граница реализованного продукта; отсутствие запланированных этапов не классифицируется здесь как ошибка уже реализованного кода.

## 3. Что действительно реализовано

| Сценарий | Реализация | Оценка |
|---|---|---|
| Читать Strict DOCX | `Package::open_*` → `StrictDocument::from_package` → `parse_document` | Работает; поддержка отдельных механизмов отражается в Feature Report |
| Читать Transitional DOCX | `ConformancePolicy::Normalize` + `TransitionalNormalizer`, CLI `--transitional` | Работает с преобразованиями и допустимыми потерями |
| Сохранить Strict DOCX | `write_package(document, source, options)` | Запись реализована; есть схемные дефекты A09, требуется исходный `Source` для медиа и немоделируемых частей |
| PDF → модель → Strict DOCX | `PdfDocument` → `convert_pdf` → `MediaBag` → `write_package` | Путь завершен технически, но обнаружены дефекты результата |
| Показать DOCX | `render_svg`, `render_pdf`, локальный `strict-ooxml-view` | Реализовано в пределах поддержки рендерера |
| Править и сохранить | `StrictDocument::document_mut()` → `write_package` → повторное открытие | Работает для программных правок; вызывающий код отвечает за согласованность |
| Открыть/импортировать/править/сохранить в едином UI | В просмотрщике только каталог DOCX и чтение страниц | Полный пользовательский сценарий не реализован |

Основные источники: `strict-ooxml/src/lib.rs:91,105,140,159,208,272,324`; `strict-ooxml-cli/src/main.rs:54,92,108,555,679`; `strict-ooxml-convert/src/lib.rs:427`; `strict-ooxml-view/src/catalog.rs:34,122`; `strict-ooxml-view/src/main.rs:133`.

### Сохранение и исходные данные

DOM не содержит байты всех ресурсов. При открытии DOCX `StrictDocument` сохраняет исходный `Package`; при PDF-конвертации результат содержит `document`, `report` и отдельный массив `media`. CLI собирает `MediaBag` перед записью. Сохранять только DOM без соответствующего источника недостаточно для общего случая с изображениями и pass-through.

Писатель пересоздает моделируемые части и переносит достижимые немоделируемые части, например данные диаграмм. Такой перенос помогает последующему открытию в офисном приложении, но не добавляет возможности редактировать или полноценно отображать саму диаграмму. В `docs/waivers.toml:199,218` для части документов с chart/SmartArt зафиксированы проверки только количества страниц, без проверки внешнего вида. Визуальное соответствие всего Strict нельзя выводить из этих PASS.

### Редактирование

`document_mut()` действительно присутствует в текущем коде. Тест `strict-ooxml/tests/open.rs:180` добавляет абзац, записывает документ и повторно читает его; он прошел в текущем запуске.

Одновременно документация самого accessor (`strict-ooxml/src/lib.rs:144`) прямо предупреждает: возможны неопределенный style id, рассинхронизация секций, дубли идентификаторов; `SupportModel` после правки не пересчитывается. Это существенная граница API: запись измененной модели не доказывает ее семантическую согласованность, а Feature Report после правки может описывать состояние до редактирования.

Просмотрщик обнаруживает DOCX в заданных каталогах, рендерит SVG и обслуживает чтение через `/api/documents` и `/api/document`; HTTP поддерживает GET/HEAD. В проверенных UI/API нет операции изменения или сохранения документа и нет импорта PDF. Этот компонент является просмотрщиком корпуса, а не готовым редактором.

## 5. Существенные находки

P1 — препятствует надежной приемке заявленной цепочки или дает ложную уверенность в ее сохранности. P2 — ограничивает интеграцию/наблюдаемость и требует исправления, но имеет доступный обход.

### A01 — P1. PDF-страницы теряют границы и свойства секций при записи

**Доказательство:** `probes.json`, случаи `multipage-semantic` и `multipage-visual`.

Вход: две страницы 612×792 pt и 842×595 pt, по строке текста. В обоих DOCX остаются два текста, но только один `w:sectPr`, размер последней страницы и ни одного явного page break. `visual` рендерится в **одну** страницу вместо двух. `semantic` на этом минимальном файле рендерится в **16** страниц: геометрия последней секции распространяется на весь текст и приводит к крайне узкой рабочей области. Обе команды `from-pdf` возвращают `0`.

**Причина:** `semantic.rs:219` и `visual.rs:105` накапливают `Document::sections`, но не прикрепляют промежуточные свойства секций к граничным абзацам. `strict-ooxml-write/src/package.rs:1266` пишет только `document.sections.last()` в конце body; остальные секции должны уже присутствовать в абзацах. Конвертер этот контракт не выполняет.

**Критерий исправления:** после PDF → DOCX → повторное чтение сохраняются секции и размеры всех страниц. Для `visual` две разнородные страницы остаются двумя; отдельные тесты на пустую страницу между текстовыми, трехстраничный документ и выбранный диапазон страниц. Для `semantic` допускается переукладка текста, но изменение геометрии не должно молча подменять все секции последней.

### A02 — P1. Векторная графика PDF исчезает без LossRecord

**Доказательство:** `text-and-vector.pdf` содержит текст и красный заполненный прямоугольник, нарисованный операторами `re f`. В обоих режимах получен DOCX с текстом, без `w:drawing` и без рисунка в SVG. Отчет: `nothing inferred or lost`, exit `0`.

**Причина:** PDF reader моделирует `Item::Vector`, но основной путь конвертации переносит текст и `Item::Image`. `semantic.rs:625` отбирает только изображения; `visual.rs:57,91` использует строки и тот же перенос изображений. `recover.rs:495` не отмечает отсутствие графики на странице с читаемым текстом. Некоторые линии могут использоваться как признаки таблиц, однако учет остаточной графики отсутствует.

**Критерий исправления:** каждый значимый векторный объект либо воспроизводится, либо его потеря явно записывается. Минимальная регрессия: текст плюс заполненный прямоугольник в обоих режимах; до реализации графики команда должна хотя бы возвращать статус преобразования с потерями. Проверять также график с подписями и смешанную растровую/векторную страницу.

### A03 — P1. `visual` неверно переносит даже простые координаты текста

**Доказательство:** в `text-and-vector.pdf` первая строка начинается при x=72 pt, baseline=92 pt от верхнего края. При 96 dpi это x=96 px и y≈122.667 px. В `vector-visual-svg/page-1.svg` фактически **x=192 px, y=108.8 px**. Горизонтальное смещение составляет целое дополнительное поле 72 pt. Отчет не сообщает о геометрической потере.

**Причина:** `visual.rs:66` записывает абсолютный `line.x` как отступ относительно поля; `geometry.rs:142` одновременно добавляет поля по 72 pt. Вертикальная координата первого baseline не задается: вместо нее `visual.rs:63` использует размер шрифта как первый межстрочный интервал. Последующие расстояния между baseline не восстанавливают начальное положение. Изображения через `semantic.rs:750` становятся центрированными inline-абзацами, также без исходного x/y.

**Критерий исправления:** совместная система координат поля/отступа/baseline; независимая проверка координат простого текста в трех местах страницы и изображения вне центра. Порог сравнения закрепить в pt или px, без ослабления эталона под текущий выход. Явно описать ограничения `visual`, которые еще не реализованы.

### A04 — P1. Тест сохранности 99.9% текста дает ложноположительный результат

**Источник:** `strict-ooxml-convert/tests/convert.rs:108`, цикл и ratio внутри `every_character_reaches_the_document`.

В числителе считается позиция поиска по исходной строке, а не количество действительно совпавших символов. Поэтому `abc → c` дает ratio=1.0 вместо 1/3. Даже `abc → Z` дает ratio=1.0: неудачный поиск просто доходит до конца `want`.

Точная арифметика существующего цикла независимо воспроизведена в `reproduce.py::flawed_ratio`, результаты в `probes.json`. Рабочий тест при аудите не изменялся. Его PASS не доказывает заявленный порог сохранности текста.

**Критерий исправления:** использовать число совпавших символов в корректном сравнении, LCS/edit distance либо строгую ожидаемую строку для детерминированной фикстуры. Обязательные отрицательные контроли: потеря начала, середины, конца, замена всего текста и перестановка. Отдельно решить учет пробелов и текста таблиц: текущий extractor в этом тесте обходит только верхнеуровневые абзацы и исключает whitespace.

### A05 — P1. XSD gate может закрыть реестр, не проверив ни одного результата

**Доказательство:** `xsd-no-matching-output.log`. Команда `xsd_gate.py --written docs/audit-2026-10-04 --quiet-messages` берет имена входных документов из default corpus, которым нет соответствий в указанной выходной папке. Печатать число реально проверенных выходных документов и не закрывать правила без упражняющих их случаев. Неизвестные схемные нарушения должны блокировать PASS, пока происхождение не доказано и не оформлено явно; недостаточно совпадения с конечным набором известных дефектов.

### A06 — P2. CLI не дает надежного общего статуса потерь всех стадий

### A10 — P1. Нарушение семантики каскада и прямого форматирования

**Класс отказа:** вычисленные свойства текста не соответствуют заданному оформлению из-за смешения наследования, переключаемых свойств стиля, прямого форматирования и свойств знака абзаца. Повторное явное включение свойства может его выключить. Класс потенциально затрагивает жирность, курсив и другие переключаемые свойства; для остальных свойств масштаб еще не измерен.

**Подтвержденный механизм:** `strict-ooxml-render-svg/src/style.rs:164–183,206–237,269–276,392–398`: один XOR-оператор применяется в разных контекстах. В измеренном фрагменте два явно заданных свойства — жирность и курсив — оба отсутствуют в SVG. После изолирующего изменения диагностической копии оба появляются. Это дефект вычисления представления; потеря этих полей при сохранении DOCX данной пробой не установлена.

**Метрики:**

- `format_mismatch_rate = неверные пары (run, свойство) / все проверенные пары (run, свойство)`. Сравнивать итоговые значения с независимо заданными ожиданиями, включая ожидаемое отсутствие свойства. Цель на детерминированных фикстурах — **0%**. Текущая локальная проба: **2/2 несовпадения** для выбранных жирности/курсива; это не частота дефектов в корпусе.
- `direct_format_invariance_failures`: число сценариев, где одинаковое прямое значение дает разный итог из-за дублирования или оформления знака абзаца. Цель — **0**. Инвариант относится к прямому форматированию, не к добавлению переключающего свойства в цепочку стилей.
- `model_to_render_mismatches`: число случаев, где ожидаемое итоговое свойство корректно вычислено в модели представления, но не доходит до SVG/PDF. Цель — **0**; считать отдельно от ошибок самого каскада.

**Тестовое покрытие:** таблица ожидаемых результатов для исходного состояния On/Off, отсутствующего/On/Off свойства в прямом run, стиля абзаца, цепочки `basedOn`, стиля символов и `pPr/rPr`. Обязательно разделить семантику свойств внутри стилей и прямого оформления. Включить повторяющиеся значения, явное выключение наследованного свойства, свойства только знака абзаца и сочетания с `bCs/iCs`. Ожидания хранить в фикстурах, не вычислять тем же помощником, который тестируется.

Проверять три уровня: расчет свойств; атрибуты SVG/выбранное лицо PDF; сквозной DOCX → нормализация → модель → запись → повторный рендер. Нужен отрицательный контроль: намеренное повторное XOR прямого On обязано сделать тест красным. Контрольный файл корпуса остается интеграционной регрессией; минимальные фикстуры обеспечивают покрытие класса.

### A11 — P1. Рассогласование выбора шрифта, измерения и отображения

**Класс отказа:** текст измеряется приближенными метриками или метриками одной семьи, а отображается другим шрифтом. Ошибочная маршрутизация по письменности и неизвестные названия семей усиливают рассогласование. Результат — наезд фрагментов, неверные переносы и изменение пагинации. Простая успешная генерация SVG этого не выявляет.

**Подтвержденный механизм:** `style.rs:315–329` предпочитает заданный CS-шрифт без учета текста; `font/family.rs:12–27` оставляет неизвестную семью; `font/builtin.rs:354–371` использует приближенные advances, а SVG сохраняет имя семьи. Локальная проба выявила **87,2 px выделенной ширины против 99,5 px по hmtx системного шрифта**, дефицит **12,3 px, или 12,36%**. Это сумма advances без shaping; точный браузерный overlap не измерен.

**Метрики:**

- `advance_error_px = |W_layout − W_oracle|`, `advance_error_ratio = advance_error_px / W_oracle` при `W_oracle > 0`. Оракул должен измерять тот же текст тем же выбранным лицом, размером и shaping-настройками. Для контролируемых фикстур предлагаемый бюджет округления — **≤0,25 px на фрагмент**; это новый критерий приемки, не результат уже пройденного гейта. Для длинного текста дополнительно проверять накопленную ошибку на строку.
- `font_resolution_mismatches`: измерение и отображение разрешились в разные лица/ресурсы. Цель — **0**; сравнивать идентификатор или хеш лица, а не только строку `font-family`.
- `unexpected_overlap_count`: число не предусмотренных эталоном пересечений соседних текстовых фрагментов. Цель — **0**. Использовать shaping/ink bounds независимого рендерера; разрешенные кернинг и курсивные выносы учитывать по эталону, не объявлять любое пересечение bounding boxes ошибкой.
- `line_break_mismatches` и `page_count_delta` на фиксированном эталоне: считать отдельно. При фиксированных ресурсах, размере страницы и параметрах детерминированной фикстуры цель — **0**. На произвольном корпусе пока публиковать измерения без заявления о достигнутом пороге.

**Тестовое покрытие:** кириллица, латиница, арабский/RTL и смешанные фрагменты; независимые `ascii/hAnsi/eastAsia/cs`, наличие CS-семьи у текста другой письменности; неизвестная семья и некорректное название; отсутствующий глиф; обычное, жирное, курсивное и жирное курсивное лицо; пробелы, NBSP и знак №. Проверять selection/fallback на уровне символов или shaping-run, затем реальную ширину и границы строк.

Для системных шрифтов тестировать как минимум два окружения — с запрошенной семьей и без нее. Герметичные гейты должны закреплять доступные шрифты и их хеши; неизвестная семья должна приводить к согласованной замене либо явному отказу/сообщению об ограничении. Независимый оракул — shaping выбранного лица и измерение готового SVG в закрепленном браузере/рендерере; hmtx годится для изоляции простых advances, но не заменяет shaping-тест. Отрицательный контроль: оставить в SVG другую реально разрешенную семью — тест согласованности обязан упасть, даже если текст целиком присутствует.

**Расширение A11 — доставка шрифта и моноширинные блоки.** `paint/mod.rs:20–48` и `paint/text.rs:9–60` выводят имя семьи без встраивания ресурса. В новой пробе **0 табуляций** в двух строках кода, моноширинному фрагменту выделено **144,023 px**; пример пропорционального fallback требует **106,260 px** — лишнее расстояние **37,763 px**. Реальное лицо браузера пользователя не измерено. [Доказательства](visual-programming/DIAGNOSIS.md).

Тесты A11 дополнить загрузкой **готового самостоятельного SVG** и SVG из просмотрщика в окружении без запрошенных системных семей. Дождаться загрузки шрифтов, проверить ресурс/хеш реально выбранного лица, непрерывность разноцветных run без исходных пробелов, ширину пробела, шаг моноширинных символов и сохранность indent/tab. Метрики `run_boundary_gap_error_px` и `monospace_advance_spread_px`: **≤0,25 px** на контролируемом лице с эталонным shaping. Отрицательный контроль — удалить ресурс шрифта и разрешить пропорциональный fallback: тест должен упасть. SVG-golden с правильным именем семьи без проверки ресурса недостаточен.

### A12 — P1. Вырождение геометрии таблиц при разрешении предпочтительных размеров

**Класс отказа:** предпочтительная ширина принимается за жесткую итоговую геометрию без разрешения конфликта с сеткой, содержимым и доступной областью. Нулевая/неполная ширина превращает непустую таблицу в почти нулевой контейнер; перенос по одной букве является следствием. Класс также требует проверки `auto/pct`, ширин ячеек, вложенности и объединений; дефекты всех этих вариантов пока не установлены.

**Подтвержденный механизм:** `strict-ooxml-render-svg/src/layout/table.rs:304–412`: `dxa=0` превращается в 1 px после clamp; ненулевая сетка пропорционально сжимается до этого значения. В локальной пробе сумма сетки **623,667 px**, фактическая ширина **1 px**: сохранено **0,1603%** ширины сетки, сжатие **99,8397%**. В выбранном префиксе **8/8 букв находятся на разных строках**. Изолирующее изменение ширины убирает этот перенос; пагинация меняется с 7 на 5 страниц. Пять страниц не объявляются эталоном Word.

**Метрики:**

- `table_width_error_px = |W_actual − W_expected|`. Ожидаемый размер задавать независимой фикстурой/эталонным layout с учетом доступной области и режима таблицы. Предлагаемый бюджет округления для детерминированной фикстуры — **≤0,25 px**. Сумма сетки сама по себе не является универсальным эталоном для AutoFit.
- `column_geometry_error`: максимальное отклонение границ столбцов от ожидаемых. Для детерминированных фикстур — **≤0,25 px**; проверять также, что сумма ширин соответствует ширине таблицы в том же бюджете.
- `unexpected_degenerate_table_count`: непустые таблицы, схлопнувшиеся вопреки ожидаемым размерам/ограничениям содержимого. Цель — **0**. Узкие декоративные и пустые столбцы исключать по контракту фикстуры, а не глобальным порогом минимальной ширины.
- `unexpected_single_character_line_ratio`: доля неожиданных однобуквенных строк среди непустых строк ячеек. В широких контрольных ячейках с обычными словами цель — **0%**. На корпусе это диагностический сигнал, а не универсальный FAIL: вертикальный текст и допустимые узкие колонки должны иметь отдельную классификацию.

**Класс:** tab stop трактуется только как точка перехода x, без alignment последующего сегмента и leader. Правые номера начинают рисоваться на правой границе, center/decimal также не получают собственную геометрию. Это затрагивает оглавления, формы, списки и табличную верстку текстом; не является потерей TOC-поля как такового.

**Подтверждение:** `next_tab_x` (`layout/paragraph.rs:1164–1189`) сохраняет только stop positions, а `Seg::Tab` (:590–592) меняет x без измерения следующего сегмента. Минимальная проба: **right stop=320 px**, `12` начинает на **x=320** вместо окончания на нем; `dot leader` не отрисован. В локальном документе **258 right stops**, но доля реально упражненных/неверных сегментов отдельно **не измерена**. Первый TOC-абзац уже содержит несколько записей в одном XML-абзаце с tabs и без br/cr: это ограничение входа, нельзя все слияния приписывать рендереру. [Доказательства](visual-thesis/DIAGNOSIS.md).

**Метрики:** `tab_alignment_error_px` по соответствующей опорной точке сегмента (левый/правый край, центр, decimal separator); `missing_or_wrong_leader_count`; ошибка начала/конца лидера; `tabbed_segment_overlap_count`; сохранность segment order и исходных разделителей. Цель фикстур — ошибки **≤0,25 px**, **0** пропусков/пересечений/перестановок. Для лидера проверять отдельную область между сегментами, не требовать точного количества точек без закрепленных метрик лица.

**Тесты:** left/right/center/decimal/bar/clear и default stops; dot/dash/underscore leaders; разные длины номера и заголовка, несколько run/шрифтов в сегменте, несколько tabs, стоп за границей контейнера, перенос длинной записи, RTL и разные decimal separators; вклад стилей и direct tab overrides, frame/table/text box, набор настоящих отдельных TOC-абзацев и намеренно слитый исходный абзац. Ожидаемые связи «entry → page number» задавать из структуры фикстуры, не из эвристики по видимому тексту. Отрицательный контроль — подменить right на left при той же позиции и удалить leader. Проверять actual face по A11 и реальный контейнер по A18. Произвольную реконструкцию поврежденного TOC не засчитывать как fidelity.

### A20 — P1. Несогласованная доступная ширина первой и последующих строк

**Класс:** начало строки сдвигается firstLine/hanging/tab, но ее допустимый конец вычисляется как это начало плюс общая ширина абзаца. Переносы и alignment применяются к ошибочному интервалу, поэтому текст выходит за контейнер даже при корректных размерах страницы и шрифтовых метриках.

**Подтверждение:** `build_lines` (`layout/paragraph.rs:533–539`) учитывает first offset в x, не в line_width; `place_token` (:829–841) сравнивает с line_start+line_width. Минимальная проба: страница **600 px**, firstLine **160 px**, обычные короткие слова — начало одного фрагмента **713,242 px**, то есть **113,242 px за страницей**. Это нижняя оценка выхода по началу, не ширина потерянного ink. Локальное оглавление также имеет 2 начала вне страницы; вклад рамок и tabs считать отдельно. [Доказательства](visual-thesis/DIAGNOSIS.md).

**Метрики:** `line_interval_start/end_error_px`, `unexpected_line_overflow_px`, `out_of_container_glyph_or_segment_count`, `line_break_mismatch_count`, `alignment_anchor_error_px`. Для контролируемых коротких токенов цель — **0 незаявленных выходов/ошибок переносов**, координаты **≤0,25 px**. Измерять начало и ink end отдельно; преднамеренный hanging/overflow и непрерывный длинный token имеют свой явный контракт, а не общий запрет отрицательного x.

**Тесты:** firstLine положительный/нулевой/отрицательный, hanging, асимметричные start/end, первый и последующий перенос, center/right/justify, tabs и inline object у границы, frame/table/text box, очень узкий контейнер, отступ больше его ширины, длинный token, RTL. Ожидаемый интервал каждой строки рассчитывать от границ контейнера, а не текущего cursor. Метаморфическая проверка: увеличение положительного firstLine уменьшает доступную ширину первой строки, но не перемещает правую границу. Отрицательный контроль — прибавить full line_width к сдвинутому start. Проверить SVG/PDF и независимый layout oracle с фиксированными шрифтами; перенос текста за край не устранять одним клиппингом, скрывающим потерю.

### A21 — P1. Область обтекания плавающего объекта не участвует в переносе строк

**Класс:** anchored drawing размещается поверх уже рассчитанного текста; Square/Tight/Through не формируют свободные интервалы строки с учетом объекта и wrap distances. Правильные координаты/размеры рисунка не обеспечивают правильного обтекания. Это отдельный контракт от относительной геометрии A13 и абзацных рамок A18.

**Подтверждение:** `layout/paginate.rs:190` вызывает `floating::resolve` после основного layout; резервирование (:330–337) через `floating.rs:142–149` ограничено TopAndBottom. В локальной пробе `wrapSquare bothSides`, портрет **169×169 px** и боковые distances **12 px**; **32 начала text-элементов с baseline внутри изображения**. Это индикатор, не площадь пересечения ink. Замена только Square → None в изолированном окружении дает **побайтно одинаковый SVG**. Изображение найдено по исходным байтам; проблема в потоке текста. [Доказательства](visual-routing-marketing-book/DIAGNOSIS.md).

**Метрики:** `wrap_exclusion_violation_area_px2` по реальным ink-маскам и расширенной области обтекания; `line_free_interval_error_px`, `wrap_distance_error_px`, `unexpected_text_image_collision_count`, сохранность порядка/полноты текста и привязки объекта к странице. Контролируемые Square-фикстуры: **0** незаявленных пересечений/потерь, ошибки интервалов и distances **≤0,25 px**. Не запрещать намеренное перекрытие для None/behindDoc. Число начал внутри прямоугольника — вспомогательная метрика, не замена ink-оракулу.

**Тесты:** Square bothSides/left/right/largest, None и TopAndBottom как отличающиеся режимы; Tight/Through с явным polygon и отчетом о пределах поддержки; разные distL/R/T/B, рисунок у края/в середине, несколько объектов, host и последующие абзацы, перенос объекта/текста между страницами, paragraph/page/column anchors и многоколоночная область. Отдельно проверить behindDoc/allowOverlap: разрешение объектам перекрываться не должно автоматически отменять обтекание текста. Метаморфическая пара Square → None меняет переносы при пересечении, сохраняя ресурс и позицию рисунка; увеличение distance сокращает свободный интервал. Отрицательный контроль — размещать рисунок только на этапе paint после расчета строк. Проверять SVG/PDF, фиксированный шрифт, независимые интервалы/маски; отсутствие support warning не засчитывать как fidelity.

### Дополнительные измерения существующих классов

**A19:** на структурированном оглавлении с отдельными TOC-абзацами, hyperlink и вложенными PAGEREF подтвержден переход номера на следующую строку. Правый stop **719,333 px** при границе **720 px** ошибочно становится началом номера. Первые две записи получают номер с baseline на **20,589–20,590 px** ниже заголовка; dot leader отсутствует. Добавить `unexpected_tabbed_segment_line_break_count` и тест right stop у границы, поля/гиперссылки, кешированные результаты, номера разной длины. При достаточном месте ожидать номер на той же строке; намеренно длинные записи имеют отдельный контракт. Полный пересчет всех ссылок/номеров по новой пагинации не проверен.

**A11:** theme-заголовок измерен по встроенному Carlito, выделенные ширины **123,331/188,280 px** совпадают с независимым hmtx **123,332/188,282 px**, но SVG не доставляет ресурс шрифта. Контрольная замена Times New Roman потребовала бы дополнительно **29,793/34,144 px**. Это подтверждает риск доставки/fallback, но actual face пользовательского просмотрщика и реальное наложение ink **не измерены**. Добавить theme fonts, большие/жирные заголовки, изолированные text-элементы и отсутствие локального шрифта в матрицу A11; фиксировать ресурс/хеш и actual face. Не классифицировать контрольный fallback как установленную причину конкретного пользовательского рендера. [Пробы](visual-routing-marketing-book/DIAGNOSIS.md).

### Правила измерения и расширения визуального покрытия A10–A21

Для каждого класса вести отдельные счетчики: **проверено / прошло / провалено / не измерено / допустимое исключение**. Рядом фиксировать SHA кода, хеш входа, режим нормализации, параметры страницы, шрифтовые ресурсы и версию независимого оракула. Ноль проверенных объектов не означает PASS; ошибки загрузки/рендера не исключать молча из знаменателя. Средние значения дополнять максимумом и перечнем превышений: один полностью схлопнувшийся объект не должен скрываться за средним по корпусу.

Новые пользовательские замечания добавлять в соответствующий класс с локальным измерением и новым воспроизводимым сценарием. Новый класс вводить при ином нарушенном контракте. Имена документов и подробные XML/SVG хранить в доказательствах; основной аудит описывает механизм, измеримый масштаб и тестовый контракт. Текущие измерения A10–A21 локальные, полная частота этих отказов по корпусу **не измерена**. Предложенные пороги и матрицы тестов **еще не реализованы и не пройдены**.

## 6. Ограничения, которые не следует выдавать за новые ошибки

- Полный WYSIWYG-редактор исключен из действующего ТЗ; публичный изменяемый DOM не подменяет готовый редактор.
- Semantic PDF-конверсия эвристически восстанавливает абзацы, таблицы, списки и колонки. PDF не дает исходной семантики Word. Изменение разбиения на абзацы допустимо, если контракт и отчет это отражают; молчаливая потеря содержимого недопустима.
- Полная модель/рендеринг chart/SmartArt и всех офисных расширений отсутствует. Pass-through сохраняет часть данных для внешнего потребителя, не гарантируя локального просмотра/редактирования этих данных.
- Шифрованный PDF явно отклоняется (`strict-ooxml-pdf/src/document.rs:220`, `error.rs:18`).
- OCR зависит от явно переданного `TextRecovery`/`FigureClassifier`, raster feature и доступной модели. Включение всех cargo features само по себе не включает распознавание в стандартной CLI-команде.
- Защита ZIP/XML и страничной PDF-обработки имеет лимиты и hostile-тесты; это существенная сильная сторона. Но `lopdf::Document::load_mem` выполняется до большинства страничных лимитов. Риск расширения object streams принят в `PDF-OBJSTM-BOMB` (`docs/waivers.toml:818`) и не закрывается ограничением сжатого входа. Новая эксплуатация этого риска в аудите не выполнялась.
- Нет нового доказательства 24-часового fuzz-гейта; это остается ограничением приемки, даже при прошедшем fuzz smoke.

## 8. Воспроизведение и артефакты

Из корня репозитория:

```powershell
cargo +1.92.0 test --workspace --all-features --locked
cargo +1.92.0 build -p strict-ooxml-cli --locked
python docs/audit-2026-10-04/reproduce.py
python xtool/xsd-gate/xsd_gate.py --corpus docs/audit-2026-10-04/strict-output --written docs/audit-2026-10-04/strict-output --quiet-messages
python xtool/xsd-gate/opc_gate.py --written docs/audit-2026-10-04/strict-output
python xtool/xsd-gate/xsd_gate.py --corpus docs/audit-2026-10-04/schema-input --written docs/audit-2026-10-04/schema-output
python xtool/xsd-gate/census_gate.py --cli target/debug/strict-ooxml.exe --no-build --quiet-messages
cargo +1.92.0 check -p strict-ooxml --no-default-features --features pdf --locked
```

Последняя команда должна воспроизвести найденный отказ сборки. `reproduce.py` генерирует минимальные файлы, сохраняет факты в `probes.json`, обновляет копии пяти выходных DOCX в `strict-output/` и удаляет прежние `page-*.svg` только внутри соответствующих папок своих проб перед новым рендерингом. В папке сохранены уже измеренные исходные PDF/DOCX, результаты и SVG. XSD/OPC оракулы измеряют эти пять файлов в `strict-output/`. `census_gate.py` требует локальный corpus `strict-ooxml-core/tests/docx`, часть которого не публикуется.

Команда оракула для `schema-input/schema-output` в текущем коде воспроизводит A09 и ложный PASS A05: смотреть `OUT=1` и сообщение запрещенного `val`, а не только exit. Новые пробы — воспроизводимые аудиторские доказательства, а не встроенные failing-тесты проекта. Перед исправлением дефектов соответствующие сценарии следует перенести в регрессионные тесты.
