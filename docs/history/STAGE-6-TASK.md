# Этап 6. Нормализация Transitional → Strict

**Шифр:** ZAKAZ-STAGE-6
**Основание:** `TZ-STRICT-OOXML-RUST.md` §10, Приложение 6
**Дата:** 2026-09-30

> Только требования и критерии. Код — по ходу, отдельными коммитами.

---

## 0. Постановка

Продуктовая цель: **открывать обычные `.docx` (99 % — Transitional) и работать
с ними как со Strict**, теряя как можно меньше содержимого.

Обратная совместимость (запись Transitional, поддержка исходного формата на
выходе) не требуется и не делается. Выход — один конвейер: нормализация во
входе, Strict-парсер и рендерер без изменений.

Почему это снимает главный вопрос приёмки. Гейт устроен как
`render(doc) → SSIM против WPS(doc)`. Раньше эталон требовал Strict-документа,
а таких в природе нет: поиск дал единственное хранилище (`SheetJS/
libreoffice_test-files/ooxml-strict`) с двумя файлами — `Lorem-ipsum.docx` и
`hello-world.docx`. **Эталону WPS Strict-файлом быть не требуется**: WPS
открывает Transitional, это его основной формат. Поэтому

```
эталон    = WPS рендерит ИСХОДНЫЙ .docx как есть
кандидат  = мы рендерим normalize(исходный .docx)
```

Гейт после этого проверяет не «умеем ли рисовать», а **«не теряет ли
нормализация содержимое»**, и любая потеря роняет SSIM. Это сильнее, чем
Strict-only корпус.

## 2. Ловушка, найденная до реализации

`TZ` §10.4 помечает переименования `left/right → start/end` как
«проверить по схеме» и запрещает применять неподтверждённые. Проверено по
нашему же парсеру:

| Атрибут | `strict-ooxml-wml` читает | Переименование безопасно? |
|---|---|---|
| `w:ind/@left,right` | **`start`/`end` и `left`/`right`** (`props.rs:367-376`) | да, и не нужно — парсер терпим к обоим |
| `w:pgMar/@left,right` | **только `left`/`right`** (`props.rs:734-736`) | **НЕТ** — переименование обнулит поля страницы |

То есть формально-правильное по ISO переименование `w:pgMar` молча ломает
вёрстку. Поэтому:

**Правило T3.** Переименование применяется **только** к парам, отмеченным
`verified`, и `verified` ставится лишь после теста, который строит два Strict
документа — со старым и с новым именем — и требует, чтобы модель совпала.
Неподтверждённые записи в таблице не применяются. Таблица начинается пустой
и растёт по мере подтверждения.

## 3. Таксономия потерь

Каждый снятый или переписанный элемент обязан попасть в отчёт. Классификация
по влиянию на **изображение**, а не по числу элементов: снять
`w:stylePaneFormatFilter` из `settings.xml` — не потеря, снять `w:pict` с
картинкой — потеря.

| Severity | Значение | Пример |
|---|---|---|
| `Info` | переписано без потери смысла | `w:jc/@w:val="left"` → `"start"` |
| `Ignorable` | снято, на страницу не влияет | `settings.xml`: `w:stylePaneFormatFilter`, `w:drawingGrid*`, `w:bordersDoNotSurround*` |
| `Lossy` | снято, изображение изменится | `w:object` (OLE), VML без растра, `w:compat`-эффекты |
| `Error` | продолжить нельзя | конфликт QName, значение вне Strict-домена |

Главная метрика этапа — **не «сколько элементов снято», а «сколько
`Lossy` на страницу»**. Считается по корпусу.

## 4. Критерии приёмки

Измеримые, гейтятся тестами. Все семь — про этот этап.

| # | Критерий | Как проверяется |
|---|---|---|
| **SC-1** | **Идемпотентность на Strict.** Нормализация Strict-пакета — no-op: все счётчики T1–T8 нулевые, байты частей не меняются | тест на всём нынешнем Strict-корпусе; падение = регрессия |
| **SC-2** | **Детерминированность.** Два прогона на одном входе → идентичные нормализованные байты и идентичный отчёт | тест; отчёт сортируется по `(part, line, col)`, т.к. порядок чтения частей не фиксирован (п. 10.10.5) |
| **SC-3** | **Тотальная нормализация.** `normalize(normalize(x)) == normalize(x)` | тест на корпусе |
| **SC-4** | **Нет молчаливых потерь.** Снятый элемент без записи в Loss Report — ошибка | счётчик `dropped − reported == 0`; проверяется тем же обходом, который снимает |
| **SC-5** | **Нет паник.** Весь Transitional-корпус обрабатывается без паники; сбой — `Err` | прогон корпуса в CI |
| **SC-6** | **Открываемость.** ≥ 90 % корпуса открывается и рендерится | прогон корпуса; **это головная метрика этапа** |
| **SC-7** | **Нет регрессий Strict.** Все существующие гейты и значения SSIM не меняются | `cargo test --workspace` + сверка SSIM |

### 4.1 Промежуточные контрольные точки

| # | Веха | Порог |
|---|---|---|
| M1 | T1–T2 (namespace + reltype) | открывается ≥ 50 % корпуса |
| M2 | T3–T5 (rename/value/removal) | ≥ 80 %, `Lossy` — посчитан и перечислен |
| M3 | T6–T8 (MCE, VML, инварианты) | ≥ 90 %, SC-1…SC-5 зелёные |

## 6. Что НЕ входит

- Запись Transitional / экспорт в Transitional.
- VML → растр (T7 только фиксирует потерю; подстановка растра — отдельный заказ).
- Генерация таблиц маппинга из XSD (`xtool xsd-diff`, §10.11) — таблицы живут
  в крейте как `const` с флагом `verified`; генератор — отдельная работа.
- Изменения в Strict-парсере и рендерере, кроме подтверждённых T3-пар.
- SSIM-гейт на нормализованных документах: требует WPS-эталонов, которых
  здесь нет; структура готовится, гейт включается после их появления.
