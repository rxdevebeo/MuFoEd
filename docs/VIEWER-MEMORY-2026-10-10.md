# Память просмотрщика и диагностика

11 576 МиБ в расследовании были рабочим набором PowerShell, собиравшего полный
JSON с SVG. Эти данные не доказывают расход одного документа или причину
зависания Windows. Старый PowerShell-сборщик отключён.

## Изменения

- Каждый документ читает и рисует отдельный процесс. До передачи задания Windows
  Job Object ограничивает его private committed memory двумя ГиБ. При невозможности
  назначить ограничение документ не запускается. Закрытие job завершает процесс.
- Сервер завершает процесс после 30 секунд; каждые 100 мс проверяет RSS и размер
  файла результата. Пределы: 2 ГиБ RSS, 96 МиБ JSON метаданных результата.
- Просмотр показывает все страницы. Ограничения в 200 страниц и 32 МиБ SVG
  удалены; при фактической ошибке ресурсов возвращается причина отказа.
- Дочерний процесс сохраняет SVG каждой страницы во временный файл и возвращает
  серверу только метаданные. Файлы принадлежат общему `Arc<DocumentView>` и
  удаляются при освобождении последнего владельца. Сервер читает нужную страницу
  с диска. Предел кэша метаданных — 64 МиБ / 8 документов для каждого корпуса.
  При аварийном завершении сервера оставшиеся файлы могут остаться в системном temp.
- Браузер запрашивает метаданные отдельно, затем SVG отдельных страниц. В DOM
  одновременно до шести SVG; остальные страницы имеют только рамку и номер.
  Число SVG в DOM ограничивает расход памяти браузера, а не длину документа.
  Старый API с полным SVG в одном JSON ограничивает такой ответ 96 МиБ;
  для больших документов используются metadata=1 и /api/page без отсечения страниц.
- `xtool/viewer-scan.mjs` обходит файлы последовательно, запрашивает метаданные
  без SVG, ограничивает ответ 16 МиБ и сохраняет каждый результат через fsync.
  Он не накапливает полный отчёт в памяти. Рекомендуемый запуск:

```powershell
node --max-old-space-size=256 xtool/viewer-scan.mjs --corpus cc0-docx-math --report render_out/graphics-gallery/math-scan-optimized.jsonl
```

## Журнал

По умолчанию `render_out/viewer-metrics.jsonl`; другой путь задаётся переменной
`STRICT_VIEW_LOG` перед запуском сервера. Каждая запись дописывается и синхронизируется.

- `render.begin`: имя и путь файла, размер входа, идентификатор запроса, время,
  лимиты и признак нативного ограничения Windows.
- `render.extreme-memory`: первый замер RSS выше 512 МиБ или private memory выше
  1 ГиБ, ещё до завершения обработки.
- `render.end`: время, страницы, объём SVG, измеренные пики RSS/private memory,
  outcome, причина ошибки или ограничения. `extreme=true` при длительности более
  5 секунд, SVG более 8 МиБ или превышении порога памяти.
- `response`: корпус, имя файла, размер ответа, режим metadata; `extreme=true`
  для ответа более 8 МиБ. Записи begin без end помогают найти прерванную обработку.

Пики private memory измеряются периодически; короткий пик между замерами может
быть пропущен. `peak_rss_bytes` берётся из счётчика ОС. Ошибка записи журнала
попадает в stderr. SVG и содержимое документа в журнал не записываются.

Нативный предел относится к committed memory, а не к сумме всей памяти компьютера:
[Microsoft Job Object limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information).
За пределами Windows нативного ограничения commit сейчас нет; на Linux используется
периодическая проверка `/proc`. Сервер, кэши корпусов и браузер имеют собственную память.

## Проверки

Тест `job_denies_commit_above_budget` запускает отдельный probe, назначает ему
лимит 64 МиБ и проверяет отказ VirtualAlloc на 128 МиБ. Отдельный SVG-тест
проверяет целостность сохранённой страницы, предупреждение о пропуске и ошибку,
когда в бюджет не помещается даже первая страница.

Тесты просмотрщика, браузерные F20/F07, Clippy и тесты сложной графики прошли.
Регрессионный тест подтверждает, что 201 страница не усекается. Тест владения
дисковыми страницами проверяет чтение страницы 201 и удаление каталога после
освобождения последнего владельца.
В браузерной галерее 12 успешных сценариев, включая прокрутку 24 страниц с
вытеснением SVG и пределом шесть страниц в DOM.
