## 4. Находки

### O1 (главное, требует решения заказчика). Критерий SSIM не выполнен — waiver — **[ЗАКРЫТО ЧАСТИЧНО S4F]**

> **Частично закрыто** `STAGE-4-RENDER-FIDELITY.md` + `S4F-REWORK-2.md`: эталоны
> WPS (12.1.0.28485) закоммичены, `resvg`-растеризатор и bundled-шрифты
> подключены, гейт `ssim` enforced: `strict-text` 0.9768, `strict-text-grid`
> (с `w:docGrid`) 0.9709 (≥ 0.95) + структурный инвариант (ink/corr/сдвиг
> ≤ 2 px) + инвариант страниц; `strict-profile` 2/2 страницы. См.
> `tests/ssim.rs`, `refs/README.md`, `stage-4-report.md` §10.
> **Открыто:** попиксельный SSIM по **реальному** Strict — исключение B-2
> (см. ниже), требует письменного согласования заказчика.

**Факт.** Критерий §11.2 «SSIM ≥ 95% на утверждённых тестах» **не удовлетворён**.
Метрика SSIM реализована и самопроверена (`tests/ssim.rs`: идентичные → 1.0,
искажённые → < 1.0), harness готов (`worst_score`), но:
- нет **внешних утверждённых эталонов** (Word/LibreOffice) и растеризатора;
- собственные эталоны дали бы самосогласованный результат (запрещено §8.2).

Зафиксировано как waiver в ADR-0006 и `docs/stage-4-report.md` (по аналогии с M8
Этапа 2). Структурные/детерминизм/валидность-оракулы при этом **принудительны**.

**Требуется от заказчика:** источник эталонов (Word/LibreOffice/иной
авторизованный рендер), формат (PNG), версия, допуски; после этого
`cargo test -p strict-ooxml-render-svg --test ssim` становится гейтом.

#### Исключение B-2 (`S4F-REWORK-2`). Реальный Strict под SSIM

**Факт.** Критерий S4F §4.2 требует SSIM ≥ 0.95 на наборе «≥ 1 реальный Strict
+ синтетические». Единственный реальный Strict — `strict-profile.docx` — под
попиксельный SSIM **не** проверяется: он построен на диаграммах/chart DrawingML,
которые Этап 4 не растеризует (наш рендер там практически пуст, ink ≈ 0 %);
совместимого по лицензии реального Strict-**текста** в корпусе нет
(`Esword618/unioffice` — AGPL, не коммитится).

**Решение (вариант B заказа).** Реальный Strict проверяется **только по
инварианту числа страниц** (`strict-profile` 2/2); попиксельный SSIM/структурный
инвариант применяются к текстовым Strict-фикстурам (`strict-text`,
`strict-text-grid`). Формулировка «O1 закрыт» к реальному Strict **не
применяется** до появления реального Strict-текста. Требуется письменное
подтверждение заказчика.

### O2 (существенное). Базовый корпус не рендерится: нет Strict-файлов

**Факт.** `strict-ooxml-core/tests/samples/` — 100% Transitional; рендер их
**отказывается** обрабатывать (нужна нормализация Этапа 6). Значит критерий
«100% базового корпуса рендерятся» на реальных `.docx` **не проверяется**:
Strict-путь покрыт только синтетикой в памяти. Это тот же пробел, что отмечался
на Этапах 2–3 («нет реального Strict-корпуса»).

**Требование.** Добавить ≥ 3 реальных **Strict** `.docx` (эталонных) в корпус и
прогнать по ним рендер (структурные проверки + будущий SSIM). Без этого
«рендеринг реального документа» подтверждён лишь косвенно.

### O3 (значимое, связано с O1). Метрики шрифта — приближённая модель — **[ЗАКРЫТО S4F]**

> **Закрыто** `STAGE-4-RENDER-FIDELITY.md`: добавлен бандл метрик-совместимых
> открытых шрифтов (Carlito/Caladea/Arimo/Tinos/Cousine), `BuiltinFontProvider`
> читает реальные advance-ширины через `skrifa`; маппинг семейств применяется в
> вёрстке и в SVG. Модель классов символов сохранена только как fallback для
> неизвестных семейств.

**Факт.** `BuiltinFontProvider` использует **классы символов** (advance 0.25/0.28/
0.33/0.5/0.85/1.0 em …), а не реальные advance-ширины глифов (ADR-0006, «cost of
exactness»). Это даёт детерминизм, но:
- переносы строк и позиции **не совпадут** с реальным шрифтом;
- при появлении эталонов достижение **95% SSIM маловероятно** без реальных
  таблиц метрик (data-only) для хотя бы базовых семейств.

**Требование.** Признать O3 обязательным предусловием O1: подключить реальные
таблицы метрик (например, открытые Liberation/DejaVu, data-only, `cargo-deny`
ok) — иначе SSIM-гейт недостижим по построению, и waiver не «временный».

### O4 (мелкие)

- `render(document, options)` без `MediaSource` даёт плейсхолдеры — задокументировано
  в ADR, но вводит в заблуждение; рекомендуется сделать `render` требующим
  источник либо переименовать (сейчас meta/CLI используют `render_with_media`).
- Golden SVG — только 3 снапшота (`paragraphs/table/image`); добавить списки/секции.
- Многоколоночность, `keepNext`, разрыв таблиц, EMF/WMF — базово/вне scope;
  согласуется с §2.2, но должно быть явно отражено в отчёте поддержки (Этап 3).

## 5. Что зачтено

- Крейт `strict-ooxml-render-svg` по структуре §4 заказа; meta feature `svg`
  (default `["report","svg"]`) и CLI `render` интегрированы.
- **Детерминизм**, **SVG-валидность независимым парсером**, **конечность
  координат**, **изображения (data URI)**, **выбор страниц** и **CLI-коды 0/1/2**
  подтверждены независимо.
- Производительность с большим запасом (104 стр. / 418 мс в debug).
- Независимый оракул с негативными контролями; покрытие 88.68%; CI расширен
  шагами svg_oracle/render/images/corpus и покрытием render-svg.
- Panic-safety исходников; лимиты `MAX_PAGES`/`MAX_ITEMS`; `fmt_num` не даёт
  `NaN`/`inf`/`-0`.

## 6. Вердикт

**Этап 4 принимается условно.**

- Выполнено и проверено независимо: структура вывода, детерминизм, валидность,
  быстродействие, изображения, CLI.
- **Не выполнены два визуальных критерия:** O1 (SSIM — waiver) и O2 (базовый
  корпус не рендерится). Это ядро продуктового обещания «отображает документ»,
  поэтому визуальная приёмка **открыта**.

**Обязательства (до претензии на полноценный Этап 4 / до Этапа 7):**
1. **O1** — заказчик предоставляет эталоны + растеризатор; включить SSIM-гейт ≥ 95%.
2. **O3** — подключить реальные таблицы метрик (предусловие O1).
3. **O2** — добавить ≥3 реальных Strict-документа и прогнать рендер/SSIM по ним.
4. **O4** — косметика API/golden.

Остальные критерии закрыты; waiver O1 унаследован и **явно** задокументирован
(ADR-0006, `stage-4-report.md`), что соответствует практике проекта.
