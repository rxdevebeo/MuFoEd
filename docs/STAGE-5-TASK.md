## 1. Цель этапа

Довести поддержку WordprocessingML Strict с базовой (Этапы 2/4) до
**расширенной**: колонтитулы, сноски/концевые, поля, сложные таблицы, темы,
полная нумерация, а также — вторым эшелоном — DrawingML-фигуры/группы/якоря.
Покрытие расширенных сценариев — **≥ 85 %** (ТЗ §15), Feature Report корректно
показывает частичную поддержку, регрессий по базовому корпусу нет.

Этап разбит на эшелоны; **данный заказ — 5A** (P0), 5B/5C — отдельные заказы:
- **5A (этот заказ, P0):** колонтитулы; сноски/концевые; поля; сложные таблицы
  (объединения, вложенность, повтор заголовка, разрыв по страницам); темы
  (шрифты/цвета); полная нумерация.
- **5B (P1):** DrawingML — якоря (позиционирование/обтекание), фигуры, группы;
  границы страниц; прочая графика.
- **5C (P2, опционально):** MathML/OMML.

## 3. Scope 5A

### 3.1. Входит

1. **Колонтитулы.** Парсинг parts `header*.xml`/`footer*.xml`; выбор
   default/first/even по `sectPr` + `titlePg` + `evenAndOddHeaders`; геометрия
   (margin header/footer из `pgMar`); рендер в той же SVG-странице (порядок
   отрисовки: колонтитулы под/над телом); разрыв на несколько страниц внутри
   колонтитула (если превышает область) — по правилам Word/WPS.
2. **Сноски/концевые.** Парсинг `footnotes.xml`/`endnotes.xml` (тела абзацев),
   привязка по `w:id`; нумерация (формат/начало/перезапуск); маркер в тексте
   (надстрочный) и область сносок внизу страницы/документа; перенос сносок на
   следующую страницу при нехватке места; позиции separator/continuation.
3. **Поля.** `fldSimple`, последовательности `fldChar` start/separate/end,
   `instrText`; отображение кэшированного результата по умолчанию; вычисление
   PAGE/NUMPAGES/SECTIONPAGES (двухпроходная пагинация); прочие поля — по кэшу с
   фиксацией «не вычислено» в SupportModel (не молча).
4. **Сложные таблицы.** `gridSpan` (горизонтальное объединение), `vMerge`
   (вертикальное, continue/restart), вложенные таблицы, `tblHeader`
   (повтор строки-заголовка на новой странице), разрыв таблицы по страницам с
   корректным переносом строк, фиксированные ширины колонок (`tblGrid`,
   `tblLayout`), базовые границы/заливка (`tblBorders`/`tcBorders`/`shd`).
5. **Темы.** Парсинг `theme1.xml`: `majorFont`/`minorFont` (latin/ea/cs),
   цветовая схема (`dk1..accent6/hlink/folHlink`); резолв theme-шрифтов и
   `w:themeColor`/`w:themeTint`/`w:themeShade` в каскаде стилей/ранов; рендер
   `font-family`/`fill` из темы.
6. **Нумерация.** Многоуровневые списки, `lvlText` (в т.ч. `%1.%2`, маркеры),
   форматы нумерации, `startOverride`/`lvlOverride`, restart, отступы и
   позиционирование маркера/табуляции уровней.
7. **Отчётность.** Все новые механизмы — в `SupportModel` с корректным
   статусом (`Supported`/`Partial`/`Unsupported`); реальная карта покрытия
   расширенных сценариев (не «problem-only» — см. F1 Этапа 3) для расчёта
   критерия ≥ 85 %.

### 3.2. Не входит (5B/5C и Этап 6)

- DrawingML-якоря/фигуры/группы, обтекание (5B); границы страниц (5B).
- MathML/OMML (5C, опционально).
- Нормализация Transitional (Этап 6) и VML.
- Полноценный шейпинг (кернинг/лигатуры) — отдельный заказ, если потребуется.
- Биометрическая совместимость с Word «до пикселя»; критерий — SSIM/структурный
  инвариант на утверждённых фикстурах (наследие Этапа 4).

## 4. Входы и совместимость

- **DOM** (`strict-ooxml-wml`, ADR-0004): расширять аддитивно; не ломать
  существующие типы без документированного pre-1.0 breaking-change.
  Новые части (headers/footers/footnotes/endnotes/theme) — новые узлы модели с
  локациями.
- **Рендер** (`strict-ooxml-render-svg`, ADR-0006): расширять конвейер
  «geometry → flow → paginate → paint»; колонтитулы/сноски — новые потоки;
  темы/нумерация — в каскаде (`style.rs`) и метриках.
- **Meta/CLI**: существующие `render --out`, `--pages`, `--scale` сохраняют
  контракт; отчёт (`report --text/--json`) отражает новые механизмы.

## 5. Ключевые подсистемы и требования

### 5.1. Части-пакеты (core)
- Определять части `word/headerN.xml`, `word/footerN.xml`,
  `word/footnotes.xml`, `word/endnotes.xml`, `word/theme/theme1.xml` по
  relationship-типам (не по имени файла).
- Лимиты: число частей/размер/глубина — по существующим `ResourceLimits`;
  отсутствие обязательной части (например, `footnotes.xml` при наличии ссылки)
  — ошибка с локацией, не паника.

### 5.2. Парсинг (wml)
- Реюз диспетчера/интернирования/лимитов; тела колонтитулов/сносок — те же
  блоки (`w:p`/`w:tbl`), что и тело документа.
- Конформанс: strict-namespace обязателен; Transitional-части (если попадут)
  — отказ как сейчас.
- Локации у всех новых узлов.

### 5.3. Каскад/метрики (render)
- Резолв темы: `majorHAnsi`/`minorHAnsi` → фактические семейства; themeColors →
  RGB (с tint/shade); корректный приоритет (docDefaults < стили < прямые).
- Нумерация: маркер/табуляция/отступы уровней; `%n`-подстановка.

### 5.4. Вёрстка и пагинация
- Колонтитулы: область из `pgMar` (header/footer), отрисовка на каждой
  странице; first/even; влияние на доступную высоту тела — только если Word/WPS
  так делает (подтвердить эталоном).
- Сноски: область внизу страницы; перенос при переполнении; концевыe — в конце
  раздела/документа.
- Поля PAGE/NUMPAGES: двухпроходная пагинация (первый проход — число страниц и
  номер, второй — подстановка); детерминизм при этом обязателен.
- Таблицы: алгоритм объединений, повтор заголовка, разрыв строк; не допускать
  зацикливания/переполнения (лимиты ячеек/строк).

### 5.5. SVG
- Колонтитулы/сноски/поля/темы/списки — в существующий SVG-валидный вывод; все
  координаты конечны; порядок элементов детерминирован.

## 6. Публичный API и CLI

- Сохранить совместимость `RenderOptions` (`scale`, `media`, `pages`,
  `font_provider`, `background`); при необходимости — аддитивные поля
  (например, `with_headers`, `footnotes`), со значениями по умолчанию,
  воспроизводящими текущее поведение.
- Feature Report: новые механизмы с локациями; `overall_status` учитывает
  partial/unsupported.
- (Опционально) CLI-флаги для включения/выключения областей — только если
  упрощает отладку; по умолчанию поведение Word/WPS.

## 7. Производительность, детерминизм, безопасность

- Перф: 100-стр. документ с колонтитулами/сносками/сложными таблицами —
  рендер ≤ 5 с (планка ТЗ); разбор ≤ 2 с для 100 стр.
- Детерминизм: повторный рендер/отчёт — побайтово идентичны; двухпроходная
  пагинация не вносит нестабильности.
- Паник-безопасность: без `unwrap/expect/panic/unsafe` в библиотечных путях;
  лимиты на число страниц/элементов/сносок/ячеек.

## 8. Тестирование и независимый оракул

### 8.1. Виды
- Модульные/интеграционные на каждую подсистему.
- **Сквозные** на Strict-фикстурах: колонтитулы, сноски, поля, объединённые/
  вложенные таблицы, темы, многоуровневая нумерация.
- Регрессия: базовый корпус и golden Этапа 4 не деградируют.
- Fuzz/повреждённые входы — без паник (наследие Этапов 1–2).

### 8.2. Независимый оракул (обязателен; уроки Этапов 2–4)
- **Рендер:** новые Strict-фикстуры + эталоны WPS `12.1.0.28485` (пиннинг,
  коммит), сравнение по **SSIM ≥ 0.95 + структурный инвариант (обе оси) +
  инвариант страниц** (переиспользовать harness `tests/ssim.rs`).
- **Парсинг:** внешний XML-оракул (`roxmltree`) для новых частей
  (headers/footers/footnotes/endnotes/theme) — сверка структуры/значений.
- **Отчёт:** валидация JSON внешней схемой (`jsonschema`), как на Этапе 3.
- **Колонтитулы/сноски:** независимая проверка позиций/нумерации (row/column
  профили, текст-оракул), по аналогии с Этапом 4.

### 8.3. Корпус
- Досоздать Strict-фикстуры **под каждую** подсистему 5A; где возможно — найти
  реальные Strict-документы с этими механизмами (совместимые лицензии;
  AGPL — не коммитить).
- Закрыть исключение **B-2** Этапа 4: приоритетно найти/add реальный
  Strict-**текстовый** документ, пригодный для SSIM (см. §9).

## 9. Открытые вопросы (решения до старта)

1. **B-2 (Этап 4):** получить письменное согласие на исключение реального
   Strict из попиксельного SSIM **или** предоставить реальный Strict-текст.
2. **Кэш полей vs вычисление:** какие поля вычисляем (PAGE/NUMPAGES/SECTIONPAGES
   — да), какие берём из кэша (остальные) — зафиксировать.
3. **Сноски и пагинация:** точное поведение переноса области сносок (правила
   Word/WPS) — согласовать и закрепить эталоном.
4. **Колонтитулы:** влияют ли на доступную высоту тела в выбранном эталоне
   (проверить на WPS); зафиксировать.
5. **Темы:** объём резолва (только fonts/colors или также effects/fills
   lineStyles) — предлагается fonts+colors.
6. **Порядок и границы эшелонов 5A/5B/5C** — подтвердить.

## 11. Критерии приёмки (ТЗ §15 Этап 5 + уточнения 5A)

1. **Покрытие расширенных сценариев ≥ 85 %** — по измеримой матрице
   (элементы/подсистемы), с независимым подтверждением (не самосогласованный
   отчёт).
2. **Колонтитулы:** default/first/even выбираются верно; рендерятся на
   страницах; эталон WPS — SSIM ≥ 0.95 + структурный инвариант (обе оси) +
   инвариант страниц.
3. **Сноски/концевые:** нумерация и позиции совпадают с эталоном в пределах
   допуска; переполнение переносится корректно; Feature Report отражает статус.
4. **Поля:** PAGE/NUMPAGES вычислены верно на многостраничном документе;
   прочие — по кэшу с явной фиксацией невычислимых.
5. **Сложные таблицы:** объединения/вложенность/повтор заголовка/разрыв строк —
   корректны на эталонах; нет паник/переполнений.
6. **Темы:** theme-шрифты и theme-цвета применяются; эталон совпадает.
7. **Нумерация:** многоуровневые списки/overrides/отступы — совпадают с эталоном.
8. **Feature Report** корректно указывает частичную поддержку; схема валидна
   внешним валидатором.
9. **Нет регрессий:** базовый корпус, golden и SSIM Этапа 4 — без ухудшения;
   `B-1` (grid) и `strict-profile` 2/2 сохраняются.
10. **Детерминизм**, кроссплатформенность (Linux/macOS/Windows), перф ≤ 5 с.
11. Гейты `fmt/clippy/test/doc/deny`, покрытие (core/wml/report/render-svg ≥ 80 %)
    — зелёные; CI дополнен шагами новых подсистем.

### Definition of Done (5A)

- [ ] Парсинг и рендер: колонтитулы, сноски/концевые, поля, сложные таблицы,
      темы, полная нумерация.
- [ ] Покрытие расширенных сценариев ≥ 85 % с независимым подтверждением.
- [ ] Strict-фикстуры + WPS-эталоны по каждой подсистеме (пиннинг, SHA-256,
      атрибуция); SSIM/структурный инвариант зелёные.
- [ ] Feature Report обновлён (частичная поддержка корректна); схема/оракул — ок.
- [ ] Нет регрессий Этапа 4 (в т.ч. `S4F` grid, `strict-profile` 2/2).
- [ ] Документация/ADR обновлены; отчёт этапа (`docs/stage-5-report.md`).
- [ ] Гейты и покрытие зелёные; повторная приёмка (ACCEPT-STAGE-5) пройдена.
