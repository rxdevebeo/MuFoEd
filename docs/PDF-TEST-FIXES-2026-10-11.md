# Исправление падений PDF pixel-тестов — 2026-10-11

Последующее уточнение: минимальный эксперимент подтвердил ошибку
автоматических переносов между `m:oMath`. После её исправления остаток
составляет **23 px для PDF, 24 px для SVG**, waiver закрыт, допуски
ещё раз ужесточены. Подробнее:
[MATH-PARAGRAPH-PROBE-2026-10-11.md](MATH-PARAGRAPH-PROBE-2026-10-11.md).
Ниже сохранены результаты первого этапа исправления.

## Причины и изменения

1. Точные фиксации границ PDF отстали от исправлений inline-формул и шрифтов.
   Для `05-strict-math-simple` нижняя граница улучшилась с +3 до 0 px;
   для первой страницы `strict-stage5c` — с +21 до +12 px.
   Это измеренные улучшения, а не расширение допуска.
2. `layout_display` рассчитывал смещение следующей строки как
   `first_ascent + accumulated_depth + 2`. При разной высоте уравнений
   получались лишние промежутки либо пересечения. Правильная координата
   следующей базовой линии — `accumulated_depth + next_ascent + 2`.
   Добавлен unit-тест последовательности высокого, низкого и ещё более
   высокого уравнения: полная высота должна равняться сумме их размеров
   и двух промежутков, ни одна строка не теряет высоту.

На второй странице `strict-stage5c` нижняя граница PDF улучшилась
с +241 до +193 px, сдвиг вертикального профиля — с 31 до 19 px.
Для SVG нижняя граница улучшилась с +242 до +193 px.
PDF SSIM остаётся выше 0.95: худшая страница документа — 0.9537;
SVG — 0.9539. Документ остаётся в существующем amber-списке.

SSIM, margin и допуски сдвига не ослаблены. Общий допуск extent для
`strict-stage5c` **ужесточён с 250 до 200 px**. Искусственный сдвиг
на 20 px увеличивает нижнее отклонение до 213 px и снова отклоняется.
Точные фиксации обеих страниц сохраняют чувствительность к одному пикселю.

## Остаточная разница с эталоном

Это устраняет причины двух отказов, но не означает полного визуального
совпадения второй страницы `strict-stage5c`: остаётся +193 px по нижнему краю.
Существующий WPS-эталон размещает соседние `m:oMath` горизонтально, тогда как
после AUD-50 рендерер сохраняет отдельную строку для каждого уравнения.
Math Paragraph описывает группу отдельных display-уравнений; их отдельные
строки также описаны в
[официальном OOXML Primer](https://download.microsoft.com/download/e/1/4/e14fb96f-83b8-4a2a-84db-7fa8acbe061a/Office%20Open%20XML%20Part%203%20-%20Primer.pdf).
Это отдельный вопрос сопоставимости эталона и размещения группы уравнений;
waiver `STAGE5C-P1-LAYOUT` оставлен, пока он не решён визуально.

Изменения не закоммичены.
