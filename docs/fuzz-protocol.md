# Fuzz protocol

Rework R10 + AUD-92: fixed conditions and a record template for acceptance
runs of the Stage-1/Stage-2/Stage-8 fuzz targets.

## Targets

| Target | Entry point | Invariant |
|---|---|---|
| `fuzz_zip` | `Package::open_reader` over raw bytes | no panic / no UB / no unbounded allocation |
| `fuzz_xml` | `XmlReader::new` + `next_event` to EOF | no panic / no UB / no unbounded allocation |
| `fuzz_relpath` | `canonicalize_part_name` / `resolve_target` | no panic / no UB |
| `fuzz_wml` | `Package::open_reader` + `parse_document` | no panic / no UB |
| `fuzz_normalize` | `TransitionalNormalizer::normalize` + `XmlReader` on `Cow::Owned` | no panic; rewritten output is well-formed XML |
| `fuzz_docx_full` | `Normalize` open → `support_report` → `render_svg` (≤3 pages) → `write_package` → reopen | no panic; successful write reopens as `Ok` |
| `fuzz_pdf` | `PdfDocument::open` → every page | no panic / no UB |
| `fuzz_convert` | `PdfDocument::open` → `convert` (semantic, no images) | no panic / no UB |

XML-ish targets may use `-dict=dict/wml.dict` (names from
`coverage/wml-elements.toml`, generated by `fuzz/gen_wml_dict.py`). Seed corpora
are filled locally by `fuzz/seed_corpus.sh` from `strict-ooxml-core/tests/{strict,docx}`
and PDF fixtures; `corpus/` and `artifacts/` stay gitignored.

## Conditions

### Plan acceptance (AUD-92 / `REWORK-AUDIT-2026-10`)

- Toolchain: `nightly` via `cargo-fuzz` on Linux (`x86_64-unknown-linux-gnu`).
- Per target, **1 hour** with reduced resource limits inside the harness and
  libFuzzer flags `-rss_limit_mb=2048 -timeout=10`:

  ```text
  cargo +nightly fuzz run --target x86_64-unknown-linux-gnu fuzz_zip -- \
    -max_total_time=3600 -rss_limit_mb=2048 -timeout=10
  # … likewise for fuzz_xml, fuzz_relpath, fuzz_wml,
  # fuzz_normalize, fuzz_docx_full (add -dict=dict/wml.dict),
  # fuzz_pdf, fuzz_convert
  ```

- Acceptance for this plan: zero crashes / timeouts / OOM across all eight
  one-hour sessions (local Linux/WSL host **or** the CI `fuzz-nightly` job after
  it has covered every target).

### Release acceptance (TZ §12.3 / Stage 7)

- Per target, a continuous session of **24 h** (`-max_total_time=86400`).
- That bar is a **Stage-7 release gate**, not a close-out criterion for
  `REWORK-AUDIT-2026-10`. Until a 24-hour record is attached below, §12.3 stays
  open for release.

## CI

- Pull requests: a 60-second smoke run of each of the eight targets
  (`fuzz-smoke` job).
- Schedule: `fuzz-nightly` runs each target for one hour with the flags above.

**AUD-92 one-hour sessions:** Windows MSVC cannot link `cargo-fuzz` (see
below). Evidence for the plan is therefore:

1. local Linux/WSL one-hour runs when a host with `clang` + `cargo-fuzz` is
   available; and/or
2. the scheduled `fuzz-nightly` job (8 × 1 h) after AUD-92 lands on `master`.

- Local execution on **Windows x86_64 (MSVC)** is not possible: `cargo-fuzz`
  cannot link the fuzzing runtime there. Both the default ASan build
  (`clang_rt.asan_dynamic_runtime_thunk-x86_64.lib` missing) and
  `--sanitizer none` (unresolved `__start___sancov_pcs` /
  `__stop___sancov_cntrs`) fail at link time. Sessions must run on a Linux or
  macOS nightly host — as the CI jobs do.
- Until a 24-hour run is attached, release acceptance rests on the
  smoke/nightly CI runs plus the property tests: `strict-ooxml-core`
  `package_open_never_panics` and `xml_reader_never_panics`, and
  `strict-ooxml-wml` `random_bytes_never_panic`, `random_bodies_never_panic`
  and `parsing_is_deterministic` (256 cases each per `cargo test`).
