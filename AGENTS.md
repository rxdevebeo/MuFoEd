# Границы изменений MuFoEd

- Не подгонять библиотеку под решения редактора. Наоборот: решения редактора адаптировать к возможностям и контрактам библиотеки, соблюдая её архитектуру и ISO/IEC 29500.
- Исправления редактора выполняются в `mufoed/` в ветке `master` основного рабочего дерева `D:/projects/StrictLib` (отдельное дерево `StrictLib-mufoed` больше не используется).
- Саму библиотеку StrictLib (библиотечные крейты `strict-ooxml*`) не изменять.
- Если для задачи потребуется изменение библиотеки, сначала согласовать с пользователем причину и предлагаемые изменения. Вносить их только после явного согласия.
- Не создавать коммиты без явного разрешения пользователя.
