# diagram-editor — MVP

Нативный редактор фигур и схем на egui 0.35. Это самостоятельный компонент
интерфейса с демонстрационным приложением. Ядро не зависит от StrictLib;
опциональный feature `docx` подключает адаптер к существующей библиотеке.

В первой версии доступны:

- прямоугольник, скруглённый блок, эллипс, ромб и текст без рамки;
- выбор фигуры или стрелки, перенос и изменение размера за нижний правый маркер;
- текст, координаты, размеры, цвет заливки/контура и размер шрифта в инспекторе;
- создание связанной стрелки двумя щелчками по фигурам;
- выбор стороны присоединения стрелки; обновление маршрута при переносе/размере;
- сетка с привязкой, масштаб и панорамирование;
- Undo/Redo, включая восстановление фигуры вместе с удалёнными связями;
- сохранение/открытие JSON и автономный экспорт SVG.

Добавлены треугольник, трапеция, шестиугольник, документ и фигурная стрелка;
толщина и пунктир контура, отсутствие заливки/контура, наконечники с двух концов;
жирный/курсив, выравнивание, поля и перенос текста. Shift+щелчок выбирает несколько
фигур. Доступны плоские группы, перенос и размер группы, дублирование с внутренними
связями, перемещение на передний/задний план. Связи остаются позади фигур.

Следующий этап реализован: выделение рамкой (Shift добавляет к выделению),
шесть команд выравнивания и равномерное распределение. Группы учитываются как
единые объекты. Доступен поворот на ±90° и произвольный угол отдельной фигуры
в инспекторе. Все команды изменяют сцену одной операцией Undo. Новые соединители
по умолчанию обходят препятствия; простой маршрут можно выбрать в инспекторе.

## Запуск

```powershell
cargo +1.92.0 run -p diagram-editor --features demo --bin diagram-editor-demo
```

Готовый release-файл после сборки: `target/release/diagram-editor-demo.exe`.

Выберите инструмент сверху и щёлкните на холсте. «Связь →» последовательно
выбирает начальную и конечную фигуры. Двойной щелчок по фигуре переводит фокус
в поле текста. Перенос выполняется левой кнопкой, панорамирование — средней
кнопкой или колесом. Ctrl+колесо меняет масштаб вокруг указателя; доступны
также кнопки масштаба и сброс вида. Delete удаляет выделенное, Ctrl+Z отменяет,
Ctrl+Y или Ctrl+Shift+Z возвращает действие. В текстовом поле сочетания
обрабатываются самим полем. Esc отменяет незавершённый перенос/создание связи.

## Встраивание

```rust,no_run
let mut editor = diagram_editor::DiagramEditor::sample();
// Внутри egui UI: editor.show(ui);
let source = editor.diagram().to_json()?;
let preview = editor.diagram().to_svg()?;
# Ok::<(), String>(())
```

`DiagramEditor::new` принимает сцену; `replace` заменяет её одной отменяемой
операцией. `diagram` отдаёт неизменяемую ссылку, а `add_node`, `update_node`,
`connect`, `select`, `delete_selected`, `undo` и `redo` позволяют управлять
редактором из приложения. `show` возвращает признак завершённого изменения,
`revision` позволяет отслеживать Undo/Redo и изменения модели.

Модель использует логические пиксели при 96 DPI, стабильные ID и явные стороны
присоединения. Привязки хранятся как ссылки на фигуры, а не координаты концов.
Один жест мышью или сеанс редактирования текста — одна запись истории.
История ограничена 128 действиями и примерно 32 МБ снимков (один снимок
сохраняется даже при превышении оценки). Лимиты модели: 1000 фигур, 2000 связей,
8192 байта текста на фигуру; JSON не больше 8 МБ. Входные данные проверяются
до замены текущей сцены. Версия JSON — 3; версии 1 и 2 читаются с миграцией. Старые соединители
сохраняют простой маршрут; отсутствующий угол фигуры равен нулю.
SVG не содержит скриптов,
внешних ресурсов или foreignObject.

## Границы MVP

Маршрутизатор обходит ограничивающие прямоугольники фигур с зазором; у повёрнутых
фигур эти прямоугольники консервативны. Простой обход проверяется для любого числа
фигур; поиск по ортогональной сетке ограничен 32 фигурами и 8712 состояниями.
При превышении лимита или невозможном пути возвращается простой маршрут с
признаком неудачи `route_status`; интерфейс и отчёт DOCX показывают предупреждение.
У повёрнутого порта короткий выходной участок также повёрнут; остальной путь
ортогональный. Пересечения соединителей между собой не устраняются.

Нет вложенных групп, произвольных контуров, переподключения концов перетаскиванием,
автоматической раскладки, градиентов и импорта SVG. Перенос подписей в превью/SVG
приближённый. В SVG используются шрифты программы просмотра, а в egui жирность
имитируется повторной отрисовкой; метрики могут отличаться. Поворот группы
представлен поворотом и позициями её участников, без вложенного преобразования.

## Локализация

Каталоги `locales/en.json` и `locales/ru.json` включены в крейт. Язык привязан к
экземпляру редактора, без глобальной переменной. Ключи — исходные английские
сообщения (gettext-style). Поддерживаются региональные теги (`ru-RU`), неполные
каталоги и английский fallback. Документ, выделение и история при смене языка
не изменяются. Локализуются инструменты, инспектор, подсказки, списки, сообщения
демонстрации и собственные диагностики/ограничения импорта и экспорта. Подробности
ошибок ОС, serde и StrictLib остаются в исходном виде.

```rust,no_run
use diagram_editor::{DiagramEditor, Locale};
let locale = Locale::new("ru-RU");
let mut editor = DiagramEditor::sample_with_locale(locale.clone());
editor.set_locale(locale.clone());
// Ошибки API остаются стабильными английскими сообщениями; перевод нужен при показе:
let message = locale.diagnostic("Invalid shape geometry or text");
// Дополнительный язык или замена отдельных сообщений из плоского JSON:
let french = Locale::new("fr").with_catalog(r#"{"Properties":"Propriétés"}"#)?;
editor.set_locale(french);
# Ok::<(), String>(())
```

В MuFoEd язык следует общему языку интерфейса, в демонстрации есть переключатель
English/Русский; начальный язык можно задать через `DIAGRAM_LANGUAGE=ru`.
`sample_with_locale` переводит подписи только создаваемого примера; смена языка
существующей сцены никогда не переводит пользовательский текст.

## DOCX

В демонстрации доступны «Экспорт DOCX» и открытие JSON/DOCX. Адаптер пользуется
публичной моделью и общим writer StrictLib, без собственной сборки ZIP/XML и
правок библиотечных крейтов. Экспортируются стандартные редактируемые фигуры,
текстовые блоки, группы и контуры соединителей. Размер холста ограничен
1800 × 2400 логических пикселей; размер страницы подбирается под схему.

Текущая модель StrictLib не хранит ссылки концов соединителя на фигуры. Поэтому
DOCX содержит редактируемые линии без привязки; экспорт возвращает явное
предупреждение. Исходные связи и неактивные цвета сохраняет JSON. При импорте
связи восстанавливаются только при однозначном совпадении концов с портами;
иначе импорт завершается ошибкой, текущая сцена сохраняется. Кегль DOCX округляется
до половины пункта с сообщением в отчёте.

Импорт рассчитан на поддерживаемый поднабор одного холста, а не на любой документ
Word. Неподдерживаемые фигуры, эффекты, преобразования, смешанное форматирование,
непредставимые маршруты линий и прочие непредставимые свойства приводят к отказу.
Проверены запись, открытие и отрисовка через StrictLib; проверка в Microsoft Word
пока не выполнена. Интеграция с MuFoEd доступна через «Вставка → Схема», контекстное меню
и двойной щелчок; применение изменений — одна операция Undo.

API: `Diagram::to_docx() -> DocxExport` и `Diagram::from_docx() -> DocxImport`.
Оба результата содержат список ограничений/преобразований `issues`.
Демонстрация также принимает путь JSON/DOCX первым аргументом командной строки.

## Проверки

```powershell
cargo +1.92.0 test -p diagram-editor --offline
cargo +1.92.0 test -p diagram-editor --features docx --offline
cargo +1.92.0 clippy -p diagram-editor --features demo --all-targets --offline -- -D warnings
cargo +1.92.0 build -p diagram-editor --features demo --bin diagram-editor-demo --release --offline
```

Тесты охватывают сохранение/повторное открытие, привязки и маршруты всех пар
портов, откат ошибочных изменений, геометрические попадания, SVG/XML, а также
события egui для переноса/масштабирования фигуры/группы и отмены жеста.
Тесты DOCX проверяют все десять геометрий, текст/стили, группы, запись/чтение,
отрисовку и явные ограничения привязок. `DIAGRAM_ARTIFACT_DIR` сохраняет примеры
DOCX, JSON и SVG при выполнении этих тестов.
Для снимка демонстрационного приложения задайте `DIAGRAM_SHOT` с путём PNG:
оно сохранит свой кадр и завершится. Это диагностический режим, а не управление
другими приложениями.
