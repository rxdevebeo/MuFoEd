**Дата:** 2026-09-30 · **Заказ:** `STAGE-8-TASK.md` (ZAKAZ-STAGE-8)

Реестр живёт отдельно от заказа: заказ описывает, что должно быть, здесь — что
**есть на самом деле**. Каждый пункт имеет измеримый выход; пункт, чей выход
недостижим в принципе, переносится в `docs/waivers.toml`.

Правило: **ни один пункт не закрывается «вроде работает»** — только замером или
независимым оракулом, как в SC-1…SC-12.

## 2. Известные ограничения уже сделанного (не дефекты, но границы)

| # | Ограничение | Следствие |
|---|---|---|
| L-1 | `PathItem` несёт контур строкой SVG-path-данных | PDF backend разбирает её обратно; общий разбор живёт в `strict-ooxml-render-pdf/src/path.rs`. Осознанный размен (ADR-0008) |
| L-2 | Кривые Безье сохраняются как кривые (`c`), а не флэтятся | для 8C обратное преобразование PDF→DrawingML потребует флэта; точность фиксируется в SC-9 |
| L-3 | Шрифты PDF (8B) — только из бандла 8 шрифтов | документ с проприетарным шрифтом получает потерю `pdf.font.missing`, а не подмену |
| L-4 | Картинка без media-источника → placeholder + запись в отчёт | `MediaMode::None` и отсутствие `Package` дают одинаковый результат намеренно |
| L-5 | Шрифт без глифа → символ не рисуется, запись `pdf.font.no_glyph` | согласованность с SVG важнее полноты |
| L-6 | GIF/BMP/TIFF/EMF/WMF/SVG в PDF не встраиваются | запись `pdf.image.unsupported`; в 8C обратное направление их читать тоже нельзя |
| L-7 | Нет выносок, аннотаций, закладок, структуры тегов, метаданных | PDF-структура минимальна: каталог, дерево страниц, ресурсы |
| L-8 | Без `/CreationDate` в PDF — намеренно, ради SC-1 | цена: файл не несёт даты; это зафиксировано в §2.2 заказа |

## 3. Места, требующие доработки по качеству

| # | Что | Почему это не «готово» | Что делать |
|---|---|---|---|
| Q-1 | **Базовый механизм вёрстки** (`render-svg::layout`) | фаза 8B сделала его публичным API; правки соседней сессии в `math/layout.rs` (интер-атомные отступы) и в `coverage/render-gates.toml` показывают, что он ещё меняется. PDF backend обязан пережить эти правки без потери SC-6 | при каждом изменении `layout` прогонять `strict-ooxml-render-pdf --test pdf`: число страниц и `MediaBox` обязаны совпасть с SVG |
| Q-2 | `place_pages` отдаёт `PlacedPage` с координатами в px | PDF считает в pt; конверсия живёт в backend. Если движок начнёт отдавать точки напрямую, бэкенд должен это учесть | держать `units::px_to_pt` единственным местом конверсии; при появлении pt-API — удалить, а не заводить второй |
| Q-3 | `ImageItem::part` добавлен в 8B | модель изображения раньше не знала, откуда взялись байты; другие backend'ы могут захотеть того же | при добавлении новых полей в `ImageItem` — обновить оба backend'а в одном коммите |
| Q-4 | Имена ресурсов изображений выводятся из part id | коллизия возможна, если два part-а дают одну очищенную строку | заменить на счётчик при первом же столкновении; сейчас `pages_are_embedded_or_recorded` коллизию не проверяет |
| Q-5 | Ширина `/W` округляется до целых 1000-unit | расхождение с точным прогоном ≤ 0.5/1000 em на глиф, накапливается по строке | для SC-6 на длинных строках проверить накопление; если > 1 px — хранить `f32` и сравнивать с запасом |
| Q-6 | Отчёт о потерях не сортируется по важности | порядок = порядок обхода; для CLI этого мало | сортировать по `severity` при выводе, порядок обхода оставить для SC-1 |
| Q-7 | Нет предела на число страниц в 8B | лимит живёт в движке вёрстки (`MAX_PAGES`), но не в PDF-сборке | при появлении внешнего входа (будущий `from-pdf`) добавить `PdfLimits` |
| Q-8 | `to-pdf` не пишет заголовок документа (title/author) | для полноты нужно из `docProps`; сейчас это вне scope | либо документировать как сознательное упущение, либо добавить в 8B.1 |
| Q-9 | Fixtures для 8B берутся из `strict-ooxml-core/tests/strict` | это `.docx`; для 8C нужен **отдельный** корпус PDF с лицензиями | собрать корпус в `strict-ooxml-pdf/tests/pdf/` с атрибуцией |
| Q-10 | `examples/dump_content.rs` в render-pdf | отладочный инструмент, не пример для пользователя | оставить, но описать в README крейта, иначе он выглядит как поддерживаемый публичный пример |
| Q-11 | Рукописные таблицы кодировок в 8C | первая версия `fonts.rs` несла таблицу MacRoman на 128 символов; копирование через PowerShell **уничтожило** её (`Ä` стал `A`), и тест это не сразу показал | брать кодировки из `encoding_rs` (`MACINTOSH`, `WINDOWS_1252`) — так и сделано; новых таблиц вручную не писать |
| Q-12 | Скан строки по относительным смещениям | первая версия `read_to_unicode` реслайсила буфер, но брала `find` у *старого* курсора, из-за чего секция `bfrange` не разбиралась **молча** | скан переписан на абсолютные смещения; правило: у текстового формата без схемы — только абсолютный курсор и тест на каждую секцию |

## 4. Проверки, которые нужно повторять при каждом изменении

```text
# гейты фаз 8A/8B
cargo fmt --all -- --check
cargo clippy -p strict-ooxml-write -p strict-ooxml-render-pdf \
             -p strict-ooxml-render-svg -p strict-ooxml -p strict-ooxml-cli \
             --all-targets --all-features -- -D warnings
cargo test -p strict-ooxml-write -p strict-ooxml-render-pdf --all-features
cargo run -p strict-ooxml-cli -- to-pdf <file.docx> --out out.pdf

# независимый оракул текста (обязателен после любой правки шрифтов)
python -c "from pypdf import PdfReader; print(PdfReader('out.pdf').pages[0].extract_text())"

# общий гейт проекта — падает, пока соседняя сессия не закончит rework
cargo test -p strict-ooxml-render-svg --test ssim
```

**Правило для регрессий движка:** любая правка `render-svg::layout` обязана
проходить `strict-ooxml-render-pdf --test pdf` в том же коммите. PDF backend —
это теперь второй потребитель раскладки, и он ловит регрессии, которых не видит
SVG-гейт (например, если координата стала не-конечной).
