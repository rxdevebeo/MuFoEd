# Image Studio / image-editor

Первый работающий срез: Rust-крейт с API, встраиваемым egui-редактором и отдельным демонстрационным приложением. Новый пакет независим от библиотечных крейтов StrictLib. В корневом Cargo workspace добавлен только новый member; существующие крейты не изменяются.

## Устройство

- `Document` / `Raster`: RGBA8 sRGB, слои снизу вверх, прозрачность, общий inpaint-mask, ручные операции, проектный формат.
- `History`: undo/redo по пользовательским действиям; до 32 снимков и целевой бюджет 64 MiB на стек, с сохранением одного большого снимка.
- `ImageEditor::show`: встраиваемый egui UI; файловые диалоги реализует хост через `FileAction`.
- `generation::PipelineJob`: генерация → Img2Img с низким denoise → UltraSharp в исходном размере, один итоговый preview; все стадии используют общий runtime.
- `generation::NativeJob`: встроенный staged-адаптер компонентов Plakat с локальным ограничением памяти UNet attention, inference вне потока UI, одна активная библиотечная задача, preview → accept/discard.
- `generation::Job`: дополнительный CLI-адаптер для диагностики с изолированными входными файлами и принудительной остановкой процесса.

Plakat — настоящий inference backend и опциональная Git-зависимость самого крейта. Feature `plakat` включает прямое библиотечное встраивание на CPU, `plakat-cuda` — на CUDA, `plakat-cudnn` — на CUDA с cuDNN-свёртками. При их наличии UI по умолчанию выбирает библиотечный backend; `plakat.exe` ему не требуется. Без этих features ручной редактор собирается отдельно, а для ИИ доступен CLI-адаптер.

## Уже реализовано

- Новый прозрачный холст; импорт PNG/JPEG/WebP/BMP/TIFF.
- Слева три вкладки **Создание / Редактирование / Апскейл** для моделей; справа ручные инструменты, коррекция и слои. Общий холст в центре, независимая прокрутка панелей.
- Компоновка и размеры элементов по образцу Invoke, с синим акцентом `#2B579A` и нейтральной тёмной палитрой MuFoEd. Встраиваемый хост может применить оформление через `ui::apply_studio_style`.
- Палитра из 16 инструментов: перемещение слоя, прямоугольное выделение, лассо, кисть, ластик, кисти маски, заливка, градиент, линия/прямоугольник/эллипс, пипетка, кадрирование, рука и масштаб. Параметры активного инструмента над холстом.
- Правый док слоёв: миниатюры на шахматной подложке, drag-and-drop порядка, видимость, блокировка пикселей, имя, opacity, добавление/копирование/удаление/объединение. Цвета и свойства холста в том же доке.
- Crop, resize с Lanczos3, поворот на 90°; все слои и маска преобразуются вместе.
- Яркость, контраст, grayscale, Gaussian blur (`image`), median denoise (`imageproc`) активного слоя; alpha сохраняется.
- Undo/redo, Ctrl+Z / Ctrl+Shift+Z.
- PSD-проект со слоями и сведённым превью; маска/рецепты сохраняются служебным блоком, старый JSON читается; атомарная замена файла; экспорт PNG без наложения маски и шахматной подложки.
- Text-to-image / image-to-image / inpaint через staged adapter публичных компонентов Plakat либо CLI, параметры model/prompt/negative/seed/steps/guidance/strength/cache.
- Результат принимается новым слоем вместе с использованными параметрами генерации. Для img2img/inpaint отвергается принятие результата, если исходный холст уже изменён.
- За пределами inpaint-mask адаптер восстанавливает исходные пиксели, даже если модель изменила весь кадр.

Это основа редактора, не полная функциональная копия Invoke или профессиональный RAW/PSD-редактор.

## Запуск

На Windows: двойной щелчок по `image-editor/start.bat`. Можно также перетащить изображение на BAT-файл, чтобы сразу открыть его в редакторе. BAT вызывает `start.ps1` и использует встроенный CUDA/cuDNN backend с оптимизированными вычислительными зависимостями. cuDNN 9 берётся из локального PyTorch либо `IMAGE_STUDIO_CUDNN_DIR`; настройка действует только в процессе запуска. Если cuDNN отсутствует, launcher сообщает об этом и собирает CUDA-вариант. `start.bat -LegacyCuda` явно выбирает CUDA без cuDNN.

Из корня worktree:

```powershell
cargo +1.92.0 run -p image-editor --features demo --bin image-editor-demo
```

Для подготовленной на этой машине локальной модели:

```powershell
./image-editor/start.ps1
./image-editor/start.ps1 -Image 'D:/path/photo.png'
# Релизная сборка и запуск (также start.bat -Release):
./image-editor/start.ps1 -Release
```

`start.ps1` использует `.runtime/hub` и модель `local/image-studio-sdxl`; соседний checkout `../plakat` нужен только для CLI-режима. Общее приложение также принимает `IMAGE_STUDIO_PLAKAT`, `IMAGE_STUDIO_MODEL`, `IMAGE_STUDIO_CACHE`. По умолчанию Plakat может скачивать недостающие компоненты из HF; подготовленный локальный комплект предназначен для работы без скачивания весов.

`start.ps1` по умолчанию собирает и запускает **встроенный CUDA backend**, а `-Cli` выбирает диагностическую сборку без библиотечного Plakat. При прямом встраивании в другой хост `PLAKAT_CACHE_DIR` нужно задать до запуска потоков хоста; cache в UI отображается только для чтения. `PLAKAT_NO_SDPA=1` обходит найденную в upstream ошибку выбора Metal-only SDPA на CUDA; демо и CLI-адаптер выставляют его сами на Windows. Для библиотеки из другого хоста задайте переменную при старте процесса.

## Модельные инструменты и вкладки

**Создание:** генерация по тексту либо по исходному изображению (img2img). В режиме img2img кнопка «Загрузить исходное изображение…» открывает файл на холсте с обычным подтверждением несохранённых изменений; источником становится композит холста. Prompt, negative prompt и denoising strength управляют преобразованием. Результат сначала предлагается для принятия.

Модель и LoRA выбираются в отдельных диалогах. Локальная библиотека по умолчанию сканирует `D:/Models` (`IMAGE_STUDIO_MODELS` переопределяет путь), читая только ограниченные заголовки safetensors. Есть поиск, семейство, статус готовности, импорт отдельного файла и подготовка checkpoint. Сканирование ограничено глубиной 3 и 10000 записями; каталоги зависимостей и symlink пропускаются. Неопределённые архитектуры checkpoint не запускаются автоматически. Неизвестное семейство LoRA показывается явно; известная несовместимость отклоняется.

Вкладка Civitai в этих диалогах ищет Checkpoint или LoRA, фильтрует базовую модель, показывает версии/файлы/размер/trigger words и ссылку на условия автора. Поддерживается cursor pagination. Скачиваются только safetensors с SHA256; файл публикуется после проверки хеша и роли тензоров, существующие файлы не перезаписываются. Токен можно ввести в скрытое поле или передать через `CIVITAI_TOKEN`; он остаётся в памяти и передаётся как Bearer header. В проект изображения и receipt он не записывается. Сеть используется при явном поиске/скачивании. Загрузки помещаются в `<model folder>/Civitai`.

SDXL/SD1.5 checkpoint готовится через `scripts/prepare_asset.py` в изолированный идентификатор HF cache; исходник не меняется. Python, diffusers, локальные конфиги и токенизаторы должны быть установлены заранее. Конвертация сама не скачивает недостающие компоненты. SDXL проверен на этой машине; другие checkpoint и SD1.5 требуют отдельной проверки совместимости. Ранее подготовленный `local/image-studio-sdxl` распознаётся по receipt.

Для text-to-image есть пресеты модели и соотношений 1:1, 4:3, 3:4, 16:9, 9:16, 3:2, 2:3, собственные размеры и Swap. Новый размер не изменяет исходный холст до принятия результата; другой размер принимается как новое изображение с Undo. Img2img/inpaint сохраняют размер исходного холста, который можно заранее изменить вручную. Seed можно задать точно как u64 либо случайно обновлять на каждом запуске; сохраняется фактически использованное число. LoRA поддерживают включение/удаление и независимые веса в -2..2; шаги — 1..150. VAE необязателен: выбор локального файла запускает offline-конвертацию в отдельные Diffusers-веса. Сменный VAE использует изолированный адаптер внутренних pipeline API зафиксированного Plakat; CLI этот режим явно отклоняет.

**Редактирование:** inpaint по нарисованной маске, BiRefNet и SAM 2.1 Hiera Large. Маску можно рисовать/стирать справа, скрывать, инвертировать и задавать feather 0..128 px. Пиксели за пределами эффективной маски восстанавливаются точно после inference; feather upstream не расширяет область разрешённых изменений.

- **BiRefNet:** загрузка официальных ONNX General Tiny (214 MiB), General или Matting (928 MiB), либо выбор локального ONNX. Обрабатывается активный слой, результат содержит исходный RGB и уменьшенный alpha. Preview → принятие новым слоем с сохранением opacity и скрытием оригинала; Undo восстанавливает исходник. По умолчанию CPU, GPU через доступный ONNX provider включается отдельно. Receipt содержит источник и рассчитанный digest; у старых GitHub assets нет опубликованного SHA256, поэтому первоначальная проверка — HTTPS, размер и загрузка ONNX-графа, затем локальный digest.
- **SAM 2.1 Hiera Large:** официальные веса `facebook/sam2.1-hiera-large`, revision `665f8e2ad61cf5f53d65644ff27c8ee525124610`; конфиги и safetensors скачиваются с фиксированными SHA256. Также можно выбрать существующий Transformers model folder. Положительные/отрицательные точки ставятся на холсте, затем **Segment object**. Маска выбирается по quality score, просматривается и принимается как общая editing/inpaint mask. Есть Undo/Clear points и возвращение к ручным инструментам. **Cut out active layer using mask** создаёт прозрачный слой и скрывает оригинал. Двоичный `.pt` upstream не загружается этим адаптером напрямую: используется та же Hiera Large в официальном safetensors-представлении.

**Апскейл:** 4x-UltraSharp, AuraSR v2 либо смешивание двух результатов. По умолчанию **65% UltraSharp / 35% AuraSR v2**, отдельные настраиваемые ползунки; положительные веса нормализуются до 100%, два нуля отклоняются. Это смешивание выходных изображений одного размера, а не интерполяция несовместимых архитектур. В одиночном режиме выбранная модель даёт 100% результата.

UltraSharp умеет использовать имеющийся `D:/Models/4xUltrasharp_4xUltrasharpV10.pt` или импортированные safetensors/pth/pt с `weights_only=True`. Есть загрузка официального `Kim2091/UltraSharp` safetensors (64 MiB). AuraSR v2 скачивается из `fal/AuraSR-v2` (около 2.30 GiB) либо выбирается каталог с config.json/model.safetensors. Обе загрузки фиксируют ревизию и SHA256; pickle/ckpt для AuraSR не требуется. UltraSharp обрабатывает тайлы 128/256/512 с контекстом, AuraSR — overlapped tiles batch=1; в смеси модели запускаются последовательно. RGB увеличивается нейросетями, alpha — Lanczos. Выход ограничен 16,777,216 пикселями. Preview → новое изображение с Undo; фактическое соотношение записывается в имя слоя. Полная типизированная processing recipe для вспомогательных моделей пока не сохраняется.

BiRefNet, SAM и апскейлеры запускаются через **необязательные локальные Python-процессы**, Plakat inference остаётся встроенным Rust backend. Используется `IMAGE_STUDIO_PYTHON` или установленный Python 3.11; общий Python при работе редактора не изменяется. Требования: `scripts/requirements-model-tools.txt`. На этой машине torch/transformers/ONNX уже были установлены, а `spandrel==0.4.2` и `aura-sr==0.0.4` добавлены изолированно в `.runtime/python-packages`; Rust bridge добавляет этот каталог в PYTHONPATH. Для повторения установки только этих двух пакетов:

```powershell
python -m pip install --target image-editor/.runtime/python-packages --no-deps spandrel==0.4.2 aura-sr==0.0.4
```

Скачанные веса находятся в игнорируемых `.runtime/BiRefNet`, `.runtime/SAM2`, `.runtime/Upscale`; последующий inference выполняется локально. Отмена Python-задачи завершает и reap-ит принадлежащий worker; временный каталог живёт до окончания cleanup. Preview защищён проверкой исходных пикселей/слоя от применения к изменившемуся изображению. В managed runtime сохраняются совместимые ONNX sessions, SAM model/image embeddings и апскейлеры; см. [R03–R05](../model-runtime/R345_VALIDATION.md).

## Plakat и локальные веса

Зафиксирован upstream `vulogov/plakat` **7.9.0**, commit `ce0d67a45bc9b5f742c3772aef85afe0d15890f6`, Unlicense. Библиотека подключена по Git SHA в Cargo.toml/Cargo.lock. Соседний checkout используется только для диагностического CLI; исходники Plakat не изменяются.

```powershell
./image-editor/scripts/build-plakat.ps1
# CPU-вариант:
./image-editor/scripts/build-plakat.ps1 -Cpu
```

CUDA-конфигурация скрипта рассчитана на эту машину: RTX 5070 Ti / SM120 / CUDA 12.9 / MSVC 2022. Она включает `-allow-unsupported-compiler` для установленного MSVC 14.44. На другом оборудовании нужно выбрать соответствующую compute capability/toolchain.

Plakat ожидает HF/Diffusers-компоненты, а не произвольный монолитный checkpoint. `scripts/prepare_sdxl.py` преобразует локальный SDXL safetensors на CPU через установленный Python + diffusers + torch + transformers. Конфиги и токенизаторы также должны уже существовать локально. Скрипт использует `local_files_only=True`, не меняет исходные веса и не загружает pickle `.ckpt`.

```powershell
python image-editor/scripts/prepare_sdxl.py D:/Models/dvine_v60.safetensors `
  --config '<local SDXL config snapshot>' `
  --cache image-editor/.runtime/hub `
  --vae D:/Models/sdxl_vae.safetensors
```

В отдельном кэше создаётся `local/image-studio-sdxl`. VAE преобразуется из LDM в Diffusers layout и помещается в namespace, который Plakat использует для SDXL fp16 VAE. Это пользовательский локальный VAE, а не утверждение о происхождении или побитовой идентичности с madebyollin. Фактический источник записан в `receipt.json` рядом с преобразованными весами. Receipt включает путь, размер и SHA256 заголовка safetensors; это не SHA256 всего файла. Лицензии/ограничения самих весов сохраняются за исходными моделями.

Кэш и результаты находятся в игнорируемых `.runtime/` и `artifacts/`; веса в Git не добавляются.

## Контракты и ограничения первого среза

- До 16,777,216 пикселей, до 16 слоёв, 128 MiB исходных пикселей документа; PSD/legacy JSON до 128 MiB. Legacy JSON с числовыми массивами может достичь лимита раньше пиксельного бюджета. Пиковая память операций выше размера документа из-за рабочих буферов и undo.
- Генерация требует размеры, кратные 8. Конкретная модель может потребовать дополнительного выравнивания; несовпадающие выходные размеры отвергаются, а не неявно растягиваются.
- Слои пока полноразмерные, normal/source-over. Mask единый, белый означает regenerate. Inpaint-кандидат — полный композит исходного холста, принимаемый отдельным слоем.
- Коррекция работает в RGBA8/sRGB, без ICC/EXIF workflow, HDR/16-bit RAW и неразрушающего стека adjustment layers. Blur не является цветометрически точной обработкой полупрозрачных краёв.
- В демо есть подтверждение замены/закрытия несохранённого проекта; PNG export не сбрасывает признак несохранённых слоёв.
- Нет outpaint, ControlNet/reference/regional layers, графа workflow и параллельной очереди задач. GUI и генерация используют один активный проект/одну задачу.
- Прогресс показывает подтверждённые стадии без процентов и промежуточных изображений. Native сохраняет CPU-веса и заново создаёт отдельные device-модели по стадиям.
- Отмена native проверяется между компонентами и denoising steps; worker сохраняет lease до завершения cleanup. CLI завершает отдельный процесс.

3. **Управляемое локальное inference.** Model registry с семейством/совместимостью/локальными файлами, resident model cache, стадии/cooperative cancel/VRAM limits реализованы; следующие расширения требуют отдельной приёмки. Приёмка: веса загружаются один раз, независимые результаты двух последовательных задач, воспроизводимый seed в пределах backend, проверка на RTX 5070 Ti.
4. **Workflow и conditioning.** Типизированный DAG с версиями узлов, ControlNet/reference/regional guidance и сохранением recipe рядом с результатом. Приёмка: валидация до запуска, поведение неподдерживаемого узла явно описано, повторное выполнение сохранённого проекта.
5. **Интеграция MuFoEd.** Отдельный адаптер экспорта PNG/метаданных и вставки через существующие контракты StrictLib. Начинать после приёмки автономного редактора; библиотечные крейты не менять.

Референсы: [Plakat supported API](https://github.com/vulogov/plakat/blob/ce0d67a45bc9b5f742c3772aef85afe0d15890f6/src/api/mod.rs), [Invoke Canvas](https://invoke-ai.github.io/InvokeAI-7/users-guide/canvas/introduction/), [image](https://github.com/image-rs/image), [imageproc](https://github.com/image-rs/imageproc). От Invoke заимствована организация workflow; его код не копировался.

API и модели: [Civitai catalog](https://github.com/civitai/civitai-developer-docs/blob/main/site/reference/models.md), [BiRefNet](https://github.com/ZhengPeng7/BiRefNet), [SAM2 Transformers](https://huggingface.co/docs/transformers/model_doc/sam2), [UltraSharp](https://huggingface.co/Kim2091/UltraSharp), [AuraSR v2](https://huggingface.co/fal/AuraSR-v2), [Spandrel](https://github.com/chaiNNer-org/spandrel). Условия использования конкретных весов проверяются на их страницах.

## Ручная работа (UI01)

Узкая палитра расположена слева от холста; ИИ-панель остаётся отдельной. Цвет переднего/заднего плана, образцы цвета и слои расположены справа. Кисть поддерживает радиус, жёсткость и непрозрачность; заливка — допуск RGBA, фигуры — ширину и заполнение. Опция «По маске» ограничивает рисование общей маской; её белая область также означает изменение при inpaint. Прямоугольное выделение заменяет именно эту маску. Кадрирование требует Enter/«Применить», Escape отменяет текущий жест. Один мазок, фигура или перетаскивание opacity — один шаг Undo.

Горячие клавиши: V — перемещение, M — выделение, B/E — кисть/ластик, Q/Shift+Q — добавить/стереть маску, G/Shift+G — заливка/градиент, L — линия, U/Shift+U — прямоугольник/эллипс, I — пипетка, C — кадрирование, H — рука, Z — масштаб (левая/правая кнопка). `[`/`]` меняют радиус, X меняет цвета местами, D сбрасывает их. Ctrl+D снимает маску и отключает ограничение по ней; Ctrl+J копирует слой, Ctrl+E объединяет с нижним, Ctrl+Shift+N добавляет слой. Сочетания инструментов не срабатывают при вводе текста.

Блокировка защищает пиксели, удаление и объединение слоя; имя, видимость и opacity остаются доступны. Общие crop/resize/rotate преобразуют весь документ, включая заблокированные слои. Объединение требует двух видимых незаблокированных слоёв и запекает opacity; RGBA8 округление может менять отдельные каналы композита при наличии нижележащих слоёв. Старые проекты без поля `locked` открываются с незаблокированными слоями. Поддерживается обычный source-over, других режимов смешивания пока нет.

Воспроизводимый многослойный пример (использует ранее полученный локальный cutout): `cargo +1.92.0 run -p image-editor --example manual_workbench`. Результат — `image-editor/artifacts/manual-workbench.json`; его можно передать BAT-файлу для открытия.

## Общий менеджер моделей R03–R05

`Runtime::global` теперь managed: проверяет RAM/VRAM до allocation, сохраняет
совместимые собственные ресурсы и освобождает idle-кэш под давлением памяти.
При встраивании передавайте runtime MuFoEd через `ImageEditor::with_runtime`.
Native использует CPU-кэш весов и последовательные CLIP → UNet → VAE; Python
инструменты — persistent workers; Ollama — собственную residency с проверкой
model digest/context и подтверждённым unload. Один OOM-retry сохраняет параметры.
Подробности и аппаратные ограничения: [отчёт R03–R05](../model-runtime/R345_VALIDATION.md).

Кнопка «Память моделей» открывает замеры ОС/драйвера, оценки пика, список кэша и
последние стадии. Обновление и освобождение работают через общий manager вне UI.
`shutdown_models()` отменяет собственные image-задачи и возвращает receiver
освобождения idle-кэша. При закрытии всего host вызовите `Runtime::shutdown_async()`
и дождитесь подтверждения; standalone demo делает это автоматически.

## PSD как формат проекта

«Сохранить» в демо предлагает `image-project.psd`; «Открыть PSD» принимает PSD и
прежние JSON-проекты. BAT также открывает переданный PSD. `Document::to_psd` /
`from_psd` доступны встраивающему host; `save_project` выбирает PSD/JSON по расширению,
`open_project` распознаёт сигнатуру. Экспорт PNG по-прежнему сводит изображение.

Первый профиль: PSD v1, RGB8, обычные растровые слои с alpha, имена Unicode,
порядок, видимость, opacity, полная блокировка, cropped bounds внутри холста и
merged preview. Поддерживаются читаемые кодеком RAW/RLE/ZIP каналы; пределы
редактора — 16 слоёв, 16,777,216 пикселей, 128 MiB пикселей документа и 128 MiB файла.

Общая маска inpaint, активный слой и исходные generation recipes сохраняются в
сжатом plug-in resource `MuFoEd.Project`. Это не маска видимости слоя Photoshop.
Веса моделей в файл не добавляются. Сторонний редактор может удалить служебный блок
при пересохранении. Если блок сохранён, но PSD-слои изменились, импорт отвергает
несовпадение, чтобы не восстановить устаревшую маску или recipe.

Группы, Photoshop masks, текст, эффекты, smart objects, adjustments, иные blend
modes, частичные locks, off-canvas pixels, ICC profiles, CMYK/16/32-bit и PSB
получают явный отказ. Полная Photoshop-совместимость не заявляется.
[Приёмка PSD и команды проверки](PSD-VALIDATION.md).

## Постобработка после генерации

В UI включена по умолчанию цепочка **генерация → Img2Img (denoise 0,2; 20 шагов) →
4x-UltraSharp без изменения размера**. Параметры — в «Постобработка после генерации»:
можно отключить цепочку, изменить denoise/шаги, выбрать веса UltraSharp или CPU/GPU.
Модель генерации, prompt/negative, seed, LoRA и VAE на Img2Img-стадии сохраняются.
Новый случайный seed выбирается один раз перед всей цепочкой.

UltraSharp остаётся настоящей моделью 4×: каждый тайл с соседним контекстом
обрабатывается в 4× и уменьшается Lanczos обратно перед сборкой изображения.
Большой промежуточный кадр 4× целиком не выделяется; alpha в режиме 1× сохраняется
побитово. Это enhancement в исходном размере, а не отдельная нейросеть 1×.
В смеси/обычном ручном апскейле сохраняется прежний режим 4×.

Только полностью завершённая цепочка возвращает candidate; ошибки и отмена
не применяют промежуточные изображения к документу. Для inpaint после всей цепочки
снова восстанавливаются защищённые пиксели. Параметры постобработки сохраняются в
generation recipe слоя и служебном блоке PSD. Старые рецепты без postprocess
открываются как однопроходные. Для host API используйте PipelineJob; низкоуровневые
NativeJob/Job явно отклоняют postprocess, чтобы не записать невыполненный рецепт.

Все egui-диалоги Image Studio центрированы; файловые диалоги в demo получают
родительский eframe Frame. Встраивающий host самостоятельно обрабатывает FileAction
и задаёт родителя своим системным диалогам.
[Аппаратная приёмка и ограничения](POSTPROCESS-VALIDATION.md).

## Настройки и преобразования холста

Кнопка **Настройки…** открывает единое центрированное окно: генерация и её backend/
постобработка, BiRefNet, SAM, UltraSharp/AuraSR. Во вкладке «Редактирование» остаются
действия с фоном, выделением и маской; prompt, модель и параметры inpaint задаются
в общих настройках на вкладке «Генерация». Во вкладке «Апскейл» остаются веса смеси
и запуск; выбор метода, пути весов, скачивание, устройство и размер тайла — в настройках.

Demo автоматически сохраняет выбор модели генерации, архитектуру, размер, LoRA,
VAE и параметры инструментов в `%APPDATA%/MuFoEd/ImageStudio/settings.json`.
Для отдельного профиля можно задать `IMAGE_STUDIO_SETTINGS`. Запись атомарная,
после паузы 500 мс и при штатном закрытии. Prompt/negative текущего запроса, Civitai token и пиксели
не сохраняются в настройках; текст можно явно сохранить внутри именованного пресета. Выбранная модель восстанавливается при запуске;
веса загружаются по требованию через общий менеджер при запуске операции.
Отсутствующие файлы остаются выбранными: их можно заменить в настройках.
Повреждённый профиль отображает ошибку и не мешает запуску редактора.

Для встраивания доступны `ImageEditor::settings`, `apply_settings`, `settings_ui`
и сериализуемый `EditorSettings`. Виджет не пишет настройки на диск: это делает
demo host; MuFoEd сможет использовать собственное хранилище и окно. Cache из
профиля demo конфигурирует до создания потоков Plakat; встраивающий host должен
сделать это сам. Восстановление настроек при активной операции отклоняется.

Справа, в **Свойства → Холст**, кнопка **Размер…** открывает диалог с сохранением
пропорций размеров, масштабированием, вписыванием с прозрачными полями,
заполнением с обрезкой и изменением только границ холста. Привязка 3×3 определяет,
с какой стороны добавляются поля или обрезаются края. **Поворот…** задаёт любой
угол по часовой стрелке, с расширением холста или обрезкой по прежним границам.
Все слои и общая маска преобразуются вместе, включая заблокированные слои.
Применение создаёт один шаг Undo; отмена диалога не меняет документ.
Повороты кратно 90° сохраняют пиксели точно; произвольный угол использует bilinear
с premultiplied alpha. Новые размеры проверяются по общим пределам документа
до выделения выходных буферов.

[Проверки интерфейса и геометрии](SETTINGS-CANVAS-VALIDATION.md).

Над холстом **Ctrl + колесо мыши** изменяет масштаб просмотра (2–800%) вокруг
курсора. Без Ctrl колесо прокручивает холст; пиксели и история документа не меняются.

## DPM++ 2M Karras и длинные prompt

В **Настройки → Генерация → Сэмплер** доступны DPM++ 2M Karras и прежний DDIM.
Новый UI по умолчанию использует DPM++ 2M Karras. Старые профили настроек без
поля sampler переходят на него при загрузке; старые рецепты PSD/JSON сохраняют
прежнюю семантику DDIM. Явно сохранённый выбор сохраняется. `Request::default()`
остаётся DDIM для обратной совместимости API; для нового solver задайте
`Sampler::Dpmpp2mKarras`. Выбор наследуется стадией Img2Img и записывается в recipe.

DPM++ реализован в адаптере редактора: DPM-Solver++ второго порядка, midpoint,
Karras rho=7, конечная sigma=0. Конфигурация training betas загружается из
`scheduler/scheduler_config.json` выбранной модели. Поддерживается epsilon prediction;
v-prediction, zero-SNR и неподдерживаемые beta schedules получают явный отказ.
Этот режим требует встроенный backend: одноимённый режим закреплённого Plakat CLI
использует UniPC без корректора, поэтому CLI не выдаётся за эквивалентный solver.
StrictLib, Plakat и общий model-runtime не изменяются.

Встроенный backend автоматически делит prompt на CLIP-контексты: по 75 содержательных
токенов плюс BOS/EOS в каждом. Текст не обрезается, включая weighted prompt и
negative prompt; ручной BREAK сохраняется. CLIP-L, CLIP-G и CFG-ветви дополняются
пустыми контекстами до одинаковой длины. SDXL pooled embedding берётся из EOS
первого контекста. Предел — 16 контекстов на ветвь; превышение возвращает ошибку,
а не обрезает текст. Короткий обычный prompt сохраняет прежние BOS/EOS и padding.

SDXL VAE encode/decode выполняются в FP32: выбранный внешний VAE давал NaN при
вычислениях в FP16. UNet и CLIP на CUDA остаются в FP16; latents преобразуются на
границе стадий, а ключи VAE в общем менеджере учитывают FP32.
Для сравнения исходной генерации с Invoke отключите постобработку, затем выровняйте
CFG, разрешение, VAE, LoRA и negative prompt.

[Численные и аппаратные проверки](GENERATION-QUALITY-VALIDATION.md).

## LoRA на GPU и пресеты

В CUDA-сборке объединение LoRA с UNet, CLIP-L и CLIP-G выполняется **на GPU** в
рамках уже полученного допуска общего менеджера. Готовые веса остаются в его
CPU-кэше и повторно используются при совпадении модели, списка LoRA, их весов,
файлов и устройства. При холодной подготовке API Plakat по-прежнему сериализует
промежуточные объединённые веса; в этой реализации полностью бездисковый merge
не заявляется. В CPU-сборке объединение выполняется на CPU. Текущая стадия
показывается рядом с индикатором генерации; ошибки объединения возвращаются в UI.

Выбранные LoRA, их веса и enabled-флаги сохраняются вместе с последней моделью
между перезапусками demo. **Пресеты…** во вкладке «Создание» открывает библиотеку:
сохранить текущие настройки под именем, применить, перезаписать, удалить,
импортировать или экспортировать JSON. В пресет входят модель, LoRA/веса,
VAE, sampler, разрешение, steps, CFG, seed/случайный seed, strength, режим
генерации, параметры маски и постобработки. Тексты prompt/negative включаются
только при установленном флажке; иначе применение сохраняет текущие тексты.

Пресеты автоматически сохраняются в профиле настроек demo. Host API:
`presets`, `save_preset`, `apply_preset`, `import_presets`, `export_presets`;
библиотека включена в `EditorSettings` для будущей интеграции с MuFoEd.
Пиксели, маска документа и фиксированный startup-cache при применении не меняются.
Веса моделей не вкладываются в JSON. Отсутствующие пути можно восстановить
позже; применение во время работы моделей отклоняется. Импорт атомарный,
дубли имён не перезаписываются молча. Пределы: 64 пресета, 2 MiB JSON,
96 символов имени; профиль настроек ограничен 4 MiB.

[Проверка двух LoRA и пресетов](LORA-PRESETS-VALIDATION.md).

Инструмент **Рука** (`H`) перемещает холст перетаскиванием левой кнопкой.
Правая кнопка временно включает панорамирование при любом выбранном инструменте;
после отпускания выбранный инструмент сохраняется. Перемещать можно холст любого
размера, включая помещающийся в окне. **Подогнать** возвращает его в центр.
`Ctrl` + колесо масштабирует относительно указателя с учётом перемещения.

Ручная работа: над списком слоёв доступны **Слой из файла…**, **Трансформация…**
и **Цветокоррекция…**. Импорт сохраняет текущий документ, центрирует новое
изображение и уменьшает его только при превышении размеров холста.
Трансформация поворачивает и масштабирует текущий слой вокруг центра его
непрозрачного содержимого; края за холстом обрезаются. Размеры холста, маска
и другие слои сохраняются. Цветокоррекция включает экспозицию EV (в линейном
свете), яркость, контраст, насыщенность, тон, температуру и гамму; окно
показывает миниатюры до/после. Применение выполняется одним шагом Undo,
«Отмена» не меняет пиксели.

Во вкладке **Свойства** справа: **Очистить холст** полностью удаляет все слои
и маску, создаёт один новый прозрачный слой с обычными свойствами и сохраняет
размеры холста. Действие отменяется одним шагом Undo.
**Удалить остальные слои** сохраняет его изображение. Блокировки защищают
остальные слои от удаления этой отдельной командой. Здесь же доступны подписанная кнопка **Кадрирование · C**
(выделить область, Enter — применить, Esc — отменить) и **Пиксельная сетка**.
Сетка видна от 600% и не попадает в экспорт; настройка сохраняется в профиле.
Строки локального каталога и Civitai занимают ширину диалога выбора моделей,
LoRA и VAE.

Поворот изображения и трансформация слоя имеют интерактивный предпросмотр
на холсте: значение угла можно перетаскивать с шагом 0,01°. Окна открываются
по центру и перемещаются за заголовок, чтобы оставить изображение видимым.
Прямые направляющие помогают оценить малый наклон. До **Применить** пиксели
и Undo не меняются; **Отмена**, Esc или закрытие окна убирают предпросмотр.
GPU рисует исходные текстуры через преобразованную сетку; готовый растр
рассчитывается из исходного слоя один раз, без накопления интерполяций при
перетаскивании. Развёрнутый поворот всего документа учитывает расширение холста.

В **Трансформация… → Перспектива и объектив** доступны ручные параметры
перспективы X/Y, скоса, радиальных коэффициентов k₁/k₂ для исправления
бочкообразной/подушкообразной дисторсии. Это ручная геометрическая коррекция,
без автоматической калибровки, распознавания линий и профилей объективов.
Проекция, радиальная коррекция, угол и масштаб применяются к активному слою
одним проходом с билинейным выбором цвета в premultiplied alpha. Размеры
холста, остальные слои и маска сохраняются; края вне холста прозрачные.
Предпросмотр на сетке является приближением; полное разрешение вычисляется
при применении. Основные формулы: [OpenCV geometric transformations](https://docs.opencv.org/3.4.0/da/d54/group__imgproc__transform.html).

**Hugging Face** — отдельная вкладка в выборе модели, LoRA и VAE. Можно искать
репозитории, открыть `owner/repo` или официальную ссылку, указать branch/tag/commit
в Revision, выбрать safetensors-файл или загрузить стандартный Diffusers-пайплайн
SD 1.5/SDXL. Для private/gated-ресурсов доступен read-токен в памяти либо `HF_TOKEN`;
условия доступа принимаются на странице автора. Токен не записывается в профиль,
пресеты и receipts. [Официальный Hub API](https://huggingface.co/docs/hub/api).

Загрузка выполняется в фоне с прогрессом/отменой, привязана к commit SHA и
проверяет SHA256 весов и тип тензоров. Большие файлы читаются ограниченными
HTTP-диапазонами. Файлы поступают в `D:/Models/HuggingFace` (или выбранный каталог
библиотеки), затем подключаются через существующие Select / Prepare & select.
Необработанный UNet не считается полным checkpoint. Diffusers импортируется в
кэш модели под локальным идентификатором конкретной ревизии; ссылка публикуется
после проверки всех компонентов и подготовки CLIP tokenizer JSON. Для этой
офлайн-подготовки используются уже установленные Python/transformers
(`IMAGE_STUDIO_PYTHON`). Встроенный VAE выбирается при отсутствии явного VAE.
После перезапуска импортированные ресурсы обнаруживаются локальной библиотекой.
Форматы Flux/SD3, sharded UNet и другие несовместимые архитектуры не объявляются
готовыми моделями текущего адаптера SD 1.5/SDXL.

**Hires Fix** доступен в «Создание» под размером первого прохода: выберите
**Hires Fix · UltraSharp → Img2Img** вместо обычной постобработки. Схема:
первый txt2img → UltraSharp до заданного размера → img2img в этом размере.
Есть масштабы 1,5× / 2× / 3× / 4×, ручные ширина/высота, denoise, steps и CFG
второго прохода. Веса и устройство UltraSharp выбираются в общих настройках
генерации. Режим **Img2Img → UltraSharp · 1×** сохраняет прежнее поведение.

Оба прохода используют одну модель, prompt/negative, LoRA, VAE и разрешённый
seed. Первое и итоговое разрешения, CFG и параметры второго прохода сохраняются
в настройках, пресетах и PSD-рецепте. Steps следуют текущему контракту backend:
это длина полного расписания; denoise определяет используемую часть расписания.
Hires Fix применяется только к txt2img; переход к img2img/inpaint переключает
постобработку на прежний режим без увеличения. Итоговый размер должен превышать
первый, быть кратным 8, не превышать 4× по каждой оси и 16M пикселей.

Тайлы UltraSharp 4× пересчитываются непосредственно в итоговое разрешение с
Lanczos и общим отображением координат; полный промежуточный растр 4× не
создаётся. Каждый этап получает допуск существующего общего менеджера моделей,
включая очередь и освобождение памяти между Torch/Candle. Промежуточные картинки
не публикуются: при отмене/ошибке документ остаётся прежним, принятие результата
происходит одним шагом Undo. CUDA-проверка `hires_smoke` прошла для
512→768→768 с проверкой PSD-рецепта и освобождения резидентных моделей.


Для SDXL больше 1024×1024 пикселей и SD1.x больше 512×512 библиотечный backend автоматически
считает CFG последовательно (полный растр для каждой ветви) а VAE при размере больше 1024×1024 выполняет
тайлами 512px с перекрытием 128px и плавным смешиванием на CPU. Нейросети остаются
на выбранном устройстве, размер не уменьшается. Это снижает пик VRAM ценой
дополнительных проходов и передач памяти. Тайловый VAE может немного менять
детали/цвет из-за локального контекста и нормализации; результат не идентичен
полноразмерному VAE. До 1 048 576 пикселей сохраняется полноразмерный VAE.
Оценка VRAM учитывает квадратичный attention с head slice2 и последовательным CFG;
защитный резерв общего менеджера остаётся включён. Очень большие размеры всё
ещё могут быть отклонены. CUDA-проверка `HIRES_SMOKE_BASE=1024`:
1024→UltraSharp 1536→Img2Img 1536, SDXL, 10 шагов расписания каждого прохода,
denoise 0.3, итоговый PSD и освобождение моделей — PASS, 95.5s (исторический запуск до оптимизации; актуальные измерения ниже).


Диагностика времени включается переменной `IMAGE_STUDIO_TIMINGS` с путём к
JSONL-файлу **до запуска процесса**. По умолчанию выключена. Таймеры сохраняют
название этапа, длительность, время начала и PID; prompt, токены и пути моделей
в журнал таймеров не попадают. На измеряемых CUDA-границах включается
синхронизация, поэтому это диагностическое wall-clock время, а не сумма времён
ядер GPU. Вложенные замеры нельзя складывать с родительскими. Частичный таймер
может появиться при ошибке/отмене; завершение пайплайна подтверждается результатом.

Пример `generation_bench` запускает выбранную локальную SDXL три раза в одном
процессе: холодный кэш менеджера, затем два прогретых. Файловый кэш Windows не
очищается; прогрев означает CPU/Python cache, UNet на CUDA между этапами
по-прежнему пересоздаётся. Профиль редактора не читается/не меняется.
Параметры по умолчанию: 1024→1536, 10/10 шагов полного расписания, denoise0.3,
seed42, фиксированный натюрморт, без LoRA. Через `BENCH_STEPS`,
`BENCH_REFINE_STEPS`, `BENCH_RUNS` можно задать отдельный сценарий. Например:

```powershell
. ./image-editor/scripts/enter-cuda.ps1
$env:BENCH_STEPS='50'
$env:BENCH_REFINE_STEPS='20'
$env:BENCH_RUNS='3'
cargo +1.92.0 run -p image-editor --example generation_bench --features demo,plakat-cuda,ollama --config 'profile.dev.package.plakat.opt-level=2' --config 'profile.dev.package.sha2.opt-level=3'
python image-editor/scripts/summarize_generation_bench.py
```

Артефакты: `artifacts/generation-bench.jsonl`, `generation-bench-receipt.json`,
`generation-bench-summary.md` и `.json`. Receipt хранит параметры тестового
сценария, checksum пикселей и состояния кэша; отдельно PNG сохраняется после
последнего замера. Время компиляции, сохранения PNG/PSD и финальной очистки
не входит в время получения кандидата. `BENCH_RECEIPT` позволяет изменить путь
receipt. Пример перезаписывает свой журнал/receipt; задайте отдельные пути для
сохранения нескольких серий. Для обычного редактора после диагностики уберите
`IMAGE_STUDIO_TIMINGS` из окружения запуска.

## Ускоренный inference

Сборка из корня worktree: `cargo +1.92.0 build -p image-editor --features demo,plakat-cudnn --bin image-editor-demo --config image-editor/cargo-performance.toml`. Launcher применяет тот же конфиг; это dev-бинарник с opt-level=3 у редактора и Candle. Plakat сохраняет opt-level=2. Fast-math и изменение точности VAE не используются.

CPU-веса заранее приводятся к рабочему dtype один раз на fingerprint. CLIP conditioning кэшируется на CPU по промптам, CFG-ветви, fingerprint энкодеров/LoRA/токенизаторов, dtype и GPU identity. Эти ресурсы учитываются и выгружаются общим `model-runtime`, как остальные модели MuFoEd. Размер и SDXL time_ids рассчитываются для каждого прохода отдельно.

Inference выполняется на одном постоянном потоке, чтобы переиспользовать CUDA context и избежать сбоя Windows при уничтожении thread-local cuDNN handles. Поток не удерживает модели или lease после задания; инфраструктура CUDA живёт до завершения процесса. GPU-компоненты CLIP/UNet/VAE освобождаются между стадиями. Attention обрабатывает по две головы с полным softmax по ключам для SDXL >1 MP и SD1.x >512². При числе query tokens >16384 дополнительно обрабатывается по1024 query rows, каждая видит все keys; это устраняет полный квадратичный score buffer в SD1.5 Hires1536. Три локальных модуля UNet взяты из закреплённого Plakat с указанием исходной лицензии и SHA; исправлены остаточная группа и конкатенация sliced attention. Это точное разбиение вычисления, без приближённого attention. Резерв общего менеджера памяти сохранён.

Диагностика включается только через `IMAGE_STUDIO_TIMINGS`; обычный запуск не включает таймеры и опрос памяти. В JSONL сохраняются вложенные wall-clock интервалы с CUDA sync и наблюдения free VRAM каждые 20 ms. Вложенные интервалы нельзя складывать с родительскими. Воспроизводимое сравнение: `./image-editor/scripts/run-generation-comparison.ps1` (требует сохранённый исходный бинарник в artifacts). Результаты и ограничения: [GENERATION-OPTIMIZATION-RESULTS.md](GENERATION-OPTIMIZATION-RESULTS.md).

Ошибка SD1.5 при 512² с включённым Hires1536² и её проверка: [SD15-HIRES-MEMORY-VALIDATION.md](SD15-HIRES-MEMORY-VALIDATION.md). Admission сообщает фактический размер native-прохода и семейство модели. Размер финального Hires сохраняется отдельно от первого прохода, включая смену модели; для конечного512² следует выбрать постобработку без увеличения.

## Лента и базовое редактирование

Верхняя часть организована как лента MuFoEd: **Главная / Изображение / Выделение / Вид** и контекстная вкладка активного инструмента. Команды разделены на группы; высота ленты постоянна, её можно свернуть. Настройки моделей и диагностика памяти доступны через Вид → Настройки/Память моделей. Масштаб и вписывание находятся в строке состояния. **Вид → Панель ИИ** освобождает левую часть для ручной работы. Справа остаются слои и свойства; буфер и общие команды перенесены на ленту.

Палитра содержит десять основных кнопок. У кнопок с треугольником ПКМ раскрывает варианты: прямоугольное выделение/лассо, заливка/градиент, линия/прямоугольник/эллипс. Цвета раскрываются из двух образцов под палитрой и доступны на Главной. Горячие клавиши: B/E — кисть/ластик, M/L — выделение/лассо, G/Shift+G — заливка/градиент, Shift+L — линия, U/Shift+U — прямоугольник/эллипс, I — пипетка, C — кадрирование, H — рука, Z — масштаб. X меняет цвета, D сбрасывает чёрный/белый.

### Растр и маска

Единственный переключатель **Растр / Маска** расположен в заголовке ленты, Q меняет режим. Общие кисть, ластик, заливка, градиент, фигуры, перемещение, пипетка, коррекция, фильтры, трансформация и буфер следуют этому режиму. В режиме маски белый добавляет область, чёрный убирает, серый задаёт частичное покрытие; слои не меняются, их блокировки не мешают редактировать маску. Цвета двух режимов хранятся раздельно. Старые ManualTool::Mask/Unmask сохранены как API-псевдонимы.

### Независимое выделение

Ручное выделение теперь хранится отдельно от маски ИИ и показывается контуром. Выделение для Copy больше не затирает подготовленный inpaint. Вкладка Выделение содержит замену/добавление/вычитание/пересечение областей, инверсию, растушёвку, расширение/сжатие и выбор непрозрачных пикселей активного слоя. Shift добавляет область, Alt вычитает, Shift+Alt пересекает; режим фиксируется в начале жеста. Ctrl+A выбирает весь холст, Ctrl+D снимает выделение. Операции рисования и удаления ограничиваются покрытием выделения; пустое выделение означает работу по всему целевому растру/маске. Переключатель «Внутри маски ИИ» дополнительно ограничивает растровое рисование подготовленной маской.

Передача областей явная: **Выделение → маска**, **Маска → выделение**. Очистка маски ИИ сохраняет ручное выделение, снятие выделения сохраняет маску. Обе области участвуют в Undo и преобразованиях холста. Выделение записывается в private MuFoEd metadata PSD/legacy JSON; старые проекты открываются без ручного выделения. Это не стандартный Photoshop layer mask. Ограничения PSD-профиля сохраняются.

### Копирование и размещение

Ctrl+C копирует содержимое текущего режима в пределах ручного выделения; в режиме растра Ctrl+Shift+C копирует сведение видимых слоёв. Без выделения копируется весь растр, либо непустая маска по её границам. Мягкие края умножают alpha один раз. **Ctrl+X** вырезает, **Delete** удаляет выделенную область текущего растра/маски; заблокированный растровый слой защищён.

Ctrl+V вставляет растр новым слоем, Ctrl+Shift+V — в текущий. В режиме маски обе команды заменяют покрытие маски без создания слоёв. Изображение при вставке в маску преобразуется через luminance × alpha; маска в растр вставляется как grayscale. После вставки включается Рука: ЛКМ в рамке перемещает фрагмент, ПКМ — холст. Фон при вставке в текущий слой восстанавливается. Ручное выделение следует за вставленным объектом, поэтому повторное Copy берёт его новую позицию. Enter закрепляет, Escape отменяет, Undo/Redo сохраняет конечную позицию. Delete во время размещения отменяет вставку. Смена режима/инструмента закрепляет фрагмент.

Demo с native-clipboard использует системный RGBA-буфер; без него у виджета остаётся внутренний буфер. Если запись в системный буфер недоступна, внутренний фрагмент сохраняется. Буфер переживает замену документа, но не записывается в PSD/настройки. Текстовые поля используют обычные текстовые команды. ПКМ без перетаскивания по холсту открывает краткое контекстное меню; перетаскивание ПКМ сохраняет навигацию.

### Трансформация на холсте

**Изображение → Трансформация** или **Ctrl+T** открывает рамку активного слоя/маски с маркерами размера и поворота. Контекстная лента показывает угол, ширину/высоту, пропорции и команды Применить/Отмена. Угловые/боковые маркеры изменяют масштаб, маркер над рамкой вращает. Shift сохраняет пропорции или задаёт шаг15°. Предпросмотр выполняется GPU-мешем из исходных пикселей; ресэмплинг происходит только после Enter/Применить и отменяется одним Undo. Escape отменяет без изменения документа. Отражение по горизонтали/вертикали доступно на вкладке Изображение. Эти команды преобразуют активный слой/маску целиком; кадрирование и общий поворот/размер холста сохраняют явные назначения для всего документа.

Промпт перерисовки маски остаётся наверху вкладки ИИ «Редактирование», негативный раскрывается отдельно. Последующие принятые этапы (палочка, ретушь, кривые, маски слоёв и восстановление) перечислены в [EDITING-ROADMAP.md](EDITING-ROADMAP.md). Проверки текущего этапа: [E01-VALIDATION.md](E01-VALIDATION.md).
