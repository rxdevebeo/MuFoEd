(`purl.oclc.org/ooxml/...` namespaces), as opposed to the synthetic Strict
packages built in memory by the tests and the Transitional corpus in
`../samples/`.

**One file is deliberately named for what it is.** `annotation-ref-sdk-mixed-rels.docx`
has zero Transitional WML parts, but its root `_rels/.rels` declares
`extended-properties` with the **Transitional** relationship type in an otherwise
Strict package — Word 2009 wrote it that way. Our conformance detector refuses it,
`write` returns `Err`, and that refusal is the point: the file is evidence that
the detector works. It is renamed so that the name states the property, because a
directory whose README promises a real Strict corpus must not hold a mixed file
under a neutral name.

**Eight files have an invalid input, and that is not a reason to drop them.**
The `O14ISOStrict/` conformance fixtures carry 60–81 schema violations each, as
written by Word 2010 (`AppVersion 14.0000`). Our writer *reduces* those to 16–28 —
and that is not a merit: it rebuilds the document from our model and discards what
it cannot express. A file whose input violates the schema is the most useful kind
of adversarial material there is, so the acceptance rule for the corpus is
"verified Strict", **not** "zero violations on input".

Three repositories, three licences, every file individually attributed and
hashed. `MPL-2.0` is in the `deny.toml` allow-list for these fixtures only —
see the justification in that file, which also states plainly that
`cargo deny` cannot and does not police data files.

**No generator was available**, which is why the corpus was harvested rather than
produced: WPS, LibreOffice, pandoc, POI, docx4j, Open-Xml-PowerTools and the
Open XML SDK can all *read* Strict and none can *write* it. Every Strict file in
existence was produced by Microsoft Word through a hidden mode. The evidence is
in each file's own `docProps/app.xml`, which sits in the **Strict**
extended-properties namespace and reads `Microsoft Office Word`.

## Stage-5C repro corpus (`05`–`10`)

These five packages arrived with `STAGE-5C-REWORK-1.md` as *independent*
evidence against the self-consistent synthetic fixtures: a layout defect cannot
hide by agreeing with the generator that produced it. They are the same
hand-built Strict sample family (OMML, DrawingML shapes, a chart part) that the
rework order measured with WPS `12.1.0.28485`; the SHA-256 of each package and
of the producer's own `VERIFY.md` are recorded there.

**Provenance and licence.** The archives carried no licence file, and the
producer's `VERIFY.md` states only that samples `05`–`09` are "hand-authored
Strict packages" and that no public Strict-with-math corpus was found. They are
committed here as test fixtures of this project under the project's own
MIT OR Apache-2.0 licence, on the basis that they are purpose-built
conformance samples rather than excerpts of a third-party work. Two samples of
the same delivery are **not** committed for want of a compatible licence:

* `msword-strict-some-text.docx` — a public Microsoft sample (author Cragun,
  Randy);
* `04-libreoffice-roundtrip-strict.docx` — produced by LibreOffice.

Both are reproducible measurements instead: see
`docs/stage-5c-report.md` §5 (D1 records the `04` ink-fraction result that the
Liberation mapping fixes). The delivery ZIP archives are **not** committed
(`STAGE-5C-REWORK-1` D5).

## Status

`strict-profile.docx` **parses**: the Stage-2 parser now skips a whitespace,
comment or processing-instruction prolog before the root element
(`REWORK-WML-1.md`, finding C-3). It is exercised end to end (open, Feature
Report, SVG render) by `strict-ooxml/tests/strict_corpus.rs`, and the
declaration/newline regression is covered by
`strict-ooxml-wml/tests/prolog.rs`.

The document reports `unsupported` for mechanisms it does not model (charts,
diagrams, anchored drawings and various `settings.xml` extensions), so `check`
exits `1`; opening succeeds and `render` emits two pages (the chart/diagram
extents are reserved for pagination).

## Visual fidelity (S4F)

`strict-ooxml-render-svg/tests/ssim.rs` rasterizes our SVG with `resvg` using the
bundled metric-compatible fonts and compares it with the committed WPS
references: `strict-text` and `strict-text-grid` must reach **SSIM ≥ 0.95** plus
the structural invariant (ink coverage, row-ink correlation, ≤ 2 px vertical
drift), and every document must render the **same number of pages** as its
reference. `strict-profile` and `09-strict-math-drawing-chart` are page-count only (their DrawingML
chart parts cannot be rasterized — Stage 6 scope); every other reference is
SSIM + structurally gated. See `refs/README.md`.
